# Промпты для генерации приложения

Рассчитаны на агента, который работает в репозитории и может запускать Gradle (Claude Code, Cursor, Android Studio с ИИ-агентом). Если у вас обычный чат без доступа к файлам — вставляйте в чат содержимое нужных файлов из `docs/` и `core/` вместе с промптом.

После лицензионного аудита числовые примеры поиска обновлены по `data/golden_search.json`. Текущее происхождение данных — `docs/LICENSE_AUDIT.md`.

## Как пользоваться

1. Положите папку проекта (эту) в git-репозиторий. Скопируйте `AGENTS.md` (для Claude Code — как `CLAUDE.md`) в корень — агент будет подхватывать правила автоматически.
2. Выполняйте промпты **по порядку, один за раз**. После каждого — запустите приложение/тесты и только потом переходите к следующему.
3. Если агент отклоняется от ТЗ, ответьте: «Сверься с docs/SPEC.md п. X и docs/BUGFIXES.md и исправь», а не переписывайте требования заново.
4. Критерии приёмки в конце каждого промпта скопируйте в чат, если хотите, чтобы агент проверил себя.

Подставьте свои значения там, где указано `<…>`: applicationId (например `com.yourname.sostavslova`), название приложения.

## Этап 2. Слой данных

```text
Прочитай docs/SPEC.md (разделы 2, 3.8–3.10, 5.7) и AGENTS.md. Реализуй слой данных в :app/data. Логику правил НЕ дублируй — используй классы из :core.

1. WordRepository: загружает assets/words.txt в WordIndex ОДИН раз (Dispatchers.Default), хранит singleton, предоставляет suspend fun ensureLoaded(), val state: StateFlow<LoadState> (Loading/Ready/Error), fun search(raw): SearchResult?, fun startGame(word: String, restoredFound: List<String>): GameState, fun randomSourceWords(count: Int = 4): List<String> (слова длиной 11–12 букв, у которых не менее 20 составимых слов; кэшируй список кандидатов лениво; без повторов в одной выборке).
2. LevelsRepository: читает assets/levels.json (org.json) → List<Level>.
3. DefinitionsRepository (интерфейс + реализация на SQLiteOpenHelper): при первом запуске копирует assets/defs.db в databases/ (учитывай PRAGMA user_version: если версия в assets выше — перекопируй), fun definitionsFor(word: String): List<Definition> (поиск по нормализованному слову, ё→е), fun isAvailable(): Boolean (нет файла → false, приложение не падает). Класс Definition(display, text, notes, antonym, example). Все запросы вне UI-потока.
4. ProgressRepository на DataStore Preferences + kotlinx-serialization (один JSON-ключ на каждую сущность):
   - currentGame: (word, found: List<String>)? — незавершённая игра;
   - levelProgress: Map<String, LevelProgress> — звёзды (никогда не уменьшаются, используй LevelProgress.merge);
   - levelAnswers: Map<String, List<String>> — сохранённые ответы уровней (для восстановления).
   Методы: observeCurrentGame(), saveGame(state), clearCurrentGame(), observeLevelProgress(), saveLevelResult(level, found) (считает LevelRules.evaluate, мёрджит со старым и сохраняет ответы), levelAnswers(word).
5. Ручной DI (AppContainer в Application) или Hilt — на ваш выбор, но единый.

Тесты (JUnit/Robolectric или instrumented — что проще настроить):
- WordRepository.randomSourceWords возвращает 4 разных слова длиной 11–12, для каждого подходит ≥20 слов.
- ProgressRepository: звёзды не уменьшаются; ответы уровня восстанавливаются; clearCurrentGame не трогает levelProgress/levelAnswers.
- DefinitionsRepository без defs.db: isAvailable()=false, definitionsFor возвращает пустой список без исключений.

Приёмка: тесты зелёные; в коде нет блокирующих вызовов на главном потоке; повторный вызов ensureLoaded() не перечитывает файл.
```

```text

Приёмка (проверь вручную и перечисли в отчёте): слово «портал» → 28 слов; ввод «пар», «ПАР», «пaр»(латинская a) — второй раз «Вы уже разгадали», латинская буква отбрасывается и слово «пр» → «не менее 3-х символов»; в статистике сумма = 28.
```
