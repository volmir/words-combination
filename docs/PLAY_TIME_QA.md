Новый тест текущей кампании получает свидетельства выполнимости заданий через
`TaskRules`, отправляет реальные ответы в `ProgressRepository` и пишет время в
настоящий Preferences DataStore с OkioStorage. Звёзды не подставляются в сохранение.
Сначала каждый уровень проходится до R, затем после холодного открытия файлов —
до M; проверяется финал, наличие недобранных звёзд перед вторым проходом и 49/49
после него. Время задаётся отдельными монотонными часами теста: 1 с перед диалогом,
2 с в диалоге подсказки, 1 с на ответ; 50 с меню исключаются, повтор после M
добавляет 7 с только к общему времени. Ожидаемые суммы и первые пересечения R/M
накапливаются отдельно от репозитория времени, затем сравниваются по каждому уровню.

## Форматы и смысл показателей

Хранение — целые миллисекунды без wall-clock дат; в UI `H ч M мин S с`, без ведущих
нулей и оборачивания часов после 24. Отображение отбрасывает доли секунды, но хранение
их сохраняет. Суммировать надо миллисекунды до форматирования: сумма округлённых
строк может отличаться от форматированной общей суммы на несколько секунд.

| Вход, мс | Отображение |
|---|---|
| 0 / 999 | `0 ч 0 мин 0 с` |
| 1000 | `0 ч 0 мин 1 с` |
| 59 999 | `0 ч 0 мин 59 с` |
| 60 000 | `0 ч 1 мин 0 с` |
| 3 599 999 | `0 ч 59 мин 59 с` |
| 3 600 000 | `1 ч 0 мин 0 с` |
| 86 400 000 | `24 ч 0 мин 0 с` |
| 97 385 999 | `27 ч 3 мин 5 с` |

R — первый подтверждённый порог открытия следующего уровня/финала; M — первые
все задания уровня. После R и M активное время продолжает накапливаться при игре,
а milestone остаются прежними. Среднее/медиана/экстремумы используют накопленное
время измеренных уровней, включая реальный ноль и повторы. Неизмеренные уровни не
входят в выборку; при отсутствии выборки — «Нет измерений».
Исторический порог — «Время отсутствует», старое активное время — «Уже играл до
включения измерения: время неизвестно»; инициализация без сегмента — «Нет сохранённого
замера». Ошибка чтения показывается как ошибка, а не нулевое время.

## Остаточные ограничения и выпуск

- При аварийном убийстве до следующего checkpoint возможна потеря незаписанного
  хвоста обычно менее 60 с. Это не строгая гарантия: задержка планировщика, очередь
  и ошибка диска могут увеличить потерю. Уже подтверждённые записи сохраняются.
