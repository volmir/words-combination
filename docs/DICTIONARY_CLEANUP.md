# Очистка игровой базы

Сборка работает локально, без ИИ, API-ключей и загрузок. Она формирует
`words.txt`, `word_sources.jsonl.gz`, `levels.json`, `golden_search.json`,
`manifest.json`. Приложение получает их через существующий
`syncDictionaryAssets`. Сама очистка не меняет UI или `HAS_DEFINITIONS`;
по отдельной задаче определения уже включены — см. [LOCAL_DEFINITIONS.md](LOCAL_DEFINITIONS.md).
Текущий результат: 23 393 слова, 30 достижимых уровней и 13 исключений для
слов кампании. [Проверенный снимок состояния](PROJECT_STATUS.md).

```bash
python3 tools/build_game_data.py \
  --dump .local/dictionary/raw-wiktextract-data-2026-11-01.jsonl.gz \
  --frequency-list .local/frequency/frequencywords-2018-ru/ru_full.txt --prepare-only
```

По умолчанию выбран `--definitions-source clean`. То же действие напрямую:

```bash
python3 tools/clean_dictionary.py \
  --dump .local/dictionary/raw-wiktextract-data-2026-11-01.jsonl.gz \
  --frequency-list .local/frequency/frequencywords-2018-ru/ru_full.txt --prepare-only
```

`--prepare-only` создаёт проверенный результат в кэше, сохраняя рабочие
данные. По умолчанию используются `tools/cache/cleanup/` и
`build/reports/dictionary_cleanup/`. Повторная сборка читает исходный
снимок и кэш, а не сужает вход до уже очищенного словаря.

Поскольку в `data/` уже есть БД определений, прямую публикацию очистка
останавливает. После подготовки передайте `candidate/manifest.json`
в `build_local_definitions.py --manifest ... --out data`: слова и
согласованные с ними определения публикуются одним пакетом. Путь candidate
выводится в JSON результата очистки.

## Вход и воспроизводимость

SHA-256 локального дампа и дата 2026-11-01 сверяются с манифестом до записи
результатов. При первой сборке `--source-words data/words.txt` фиксирует
исходные 113 413 слов в кэше; затем этот параметр не нужен. Если кэша нет,
исходный полный список восстанавливается исходным отбором заголовков
`wiktionary_wordlist()` из того же дампа, без overrides. Число и SHA-256
исходного списка записаны в манифесте. Другой исходный список требует
другого `--cache`, чтобы случайно не потерять базовый набор.

Частотный список содержит словоформу и целое число употреблений. Счётчики
суммируются по уникальным формам каждой леммы, включая её заголовок;
регистр, ударения и ё нормализуются. Общие формы разных лемм могут
увеличивать частоту обеих: омонимия не снимается. Локальный `source.json`
рядом со списком, если он содержит этот файл, проверяется по SHA-256;
его сведения об источнике и лицензии переносятся в манифест. Для файла
без метаданных происхождение и лицензия не выдумываются.

Использованный FrequencyWords — список OpenSubtitles 2018, закреплённая
ревизия `f8a65e6ddc17e0baa2e366a909986798d8dbe55b`, 1 423 050 словоформ.
В README этой ревизии указана CC BY-SA 3.0 для данных. Список не копируется
в приложение и не служит источником новых слов. Это разговорный сигнал
по субтитрам, а не сбалансированный современный корпус.

## Правила первого прохода

Параметры находятся в `cleanup` файла `tools/selection_config.json`.
Старые `target_size`, `llm_candidates`, `reference_candidates`,
`overrides/add.txt`, `overrides/remove.txt` и `remove_definitions.txt`
в этом режиме не применяются.

1. Проверяются алфавит и длина 3–30, строчный заголовок нарицательного
   существительного. Эти ограничения нельзя обойти исключением уровня.
2. Пометы проверяются по структурным полям и только в начале толкования,
   а не поиском произвольных слов по всей статье. Формы и варианты,
   уменьшительные, устаревшие, диалектные, жаргонные, грубые, авторские,
   новые или редкие значения получают отдельные причины. Ограниченно
   используемые сокращения исключаются; самостоятельное существительное
   с пометой аббревиатуры допускается при минимум 100 употреблениях,
   если нет других запрещающих помет. Достаточно
   одного допустимого самостоятельного современного значения.
   Лексикализованное слово с самостоятельным значением может сохраниться,
   даже если другое его значение уменьшительное. Суффикс не является
   самостоятельным основанием отказа. Чистая отсылка к уменьшительному
   значению вместе с характерным суффиксом подтверждает уменьшительную
   форму; суффикс и упоминание другого слова по отдельности её не доказывают.
3. Для обычного слова требуется минимум 10 употреблений по всем формам.
   Ноль — `usage_unconfirmed`, 1–9 — `low_frequency`: такие слова
   откладываются на проверку, а не объявляются несуществующими.
4. Если все допустимые значения имеют узкую предметную помету или
   соответствуют признаку специализированного определения, требуется
   минимум 100 употреблений. Сама тема не является безусловным отказом.
   Общие анатомические, кулинарные и подобные пометы не считаются узкими
   автоматически. Длинное слово более 16 букв при менее 100 употреблениях
   откладывается как `compound_candidate`; длина отдельно его не исключает.
5. Слова уровней, кроме четырёх согласованно заменённых исходников, сохраняются с записью
   причин, по которым не прошли бы обычный отбор. Золотой список не даёт
   принудительного включения и не редактируется ради результата.

Наличие, длина, качество и права на определение не определяют включение
игрового слова. Толкования не публикуются в этой сборке. Имеющийся файл
`definitions.db` в каталоге назначения остановит публикацию до его
отдельного согласования с новым словарём; прежняя база в кэше сохраняется.

## Уровни, проверки и отчёт

Разрешённые замены заданы в конфиге. Для них может выбираться подходящая
буква задания, но все числовые пороги остаются прежними. Все остальные
слова, буквы и пороги сохраняются. Если задания недостижимы, рабочие данные
не заменяются; причины сохраняются в `summary.json`.

Отчёты: `decisions.csv` (каждое слово и решение), `review_words.csv`,
`rejected_by_reason.csv`, `rejection_examples.json` (до 30 примеров на
причину), `selected_random_50.csv`, `selection_sample.csv` (до 200 строк
каждого решения для ручной проверки), `level_exceptions.csv`,
`recognized_labels.json`, `summary.json`.

У результата `selection.mode=game-cleanup-v1`, хэши правил, генератора,
частотного и исходного списков; `audit.passed=false`. Это автоматический
первый проход с явными исключениями для кампании, а не завершённый ручной
аудит. Для дальнейшей чистки нужно разбирать выборку и пограничные слова,
менять общие правила и регенерировать, сохраняя журнал изменений.
