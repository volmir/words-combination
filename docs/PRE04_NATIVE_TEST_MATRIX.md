# PRE04-02: штатный экран смартфона

Изменения ограничены `app/src/androidTest` и этим отчётом. Все экранные fixture
используют естественные constraints, плотность и системный масштаб шрифта
подключённого устройства. Подмена LocalDensity, фиксированная ширина экрана и
изменение настроек телефона не используются. Production-код не менялся.

## Диагностика экрана

Снято 2026-11-17 исключительно командами чтения; идентификаторы устройства не собирались в отчёт.

| Команда | Полученное значение |
| --- | --- |
| `adb shell wm size` | Physical size: 1080x2400 |
| `adb shell wm density` | Physical density: 440 |
| `adb shell settings get system font_scale` | 1.0 |

## Старые display-варианты → новый единый native-вариант

Перечислены все восемь изменённых тестовых классов. Число запусков — число
методов `@Test`, умноженное на число параметров JUnit, а не замер времени.
Native означает фактическую конфигурацию устройства, а не зафиксированные в коде
значения из диагностической таблицы.

| Класс | Старые display-варианты | Новый display-вариант | Запуски JUnit: было → стало |
| --- | --- | --- | --- |
| `CampaignGameUiTest` | width 320/360/400 × font 1/1.5/2 плюс 840 × 1 (10) | native | 8 × 10 = 80 → 8 |
| `FoundWordsSectionTest` | width 320/360/400 × font 1/1.5/2 (9) | native для каждого legacy/v2 | 2 × 9 × 2 = 36 → 4 |
| `LevelsLayoutTest` | width 320/840 × font 1/2 (4) | native | 4 → 1 |
| `GameLayoutTest` | width 360 × font 1; width 320 × font 2 (2) | native | 2 → 1 |
| `ComponentLayoutTest` | width 360 × font 1; width 320 × font 2 (2) | native для каждого компонента | 10 × 2 = 20 → 10 |
| `TimeScreenTest` | один из трёх методов внутри повторял width 320/360 при font 2 | native, один проход | 3 → 3 |
| `ComponentInteractionTest` | один из девяти методов задавал font 2 | native | 9 → 9 |
| `TextLayoutAssertionsTest` | Text с шириной 120 dp, без display-параметризации | native; явный перевод строки в синтетическом тексте | 6 → 6 |

Итого для этих классов: **160 → 42**, на **118 запусков (73,75%) меньше**.
Дополнительно в `TimeScreenTest` проход проверки всех 6 этапов и 15 уровней
выполняется один раз вместо двух. Остальные классы и их число запусков не меняются.
Сокращение длительности всей instrumented-сюиты не измерялось.

## Сохранённые логические параметры и сценарии

- `CampaignGameUiTest`: все восемь методов, T1–T7, реальные задания каждого
  установленного уровня, загадки и изменения их решения, группы слов и статистика;
  цена и бюджет подсказок, собственное определение и маскирование, порядок частей,
  открытые части 0/1/3/5, восстановление состояния, смена/нахождение цели,
  fallback на буквы, исчерпание подсказок, смена уровня с сохранением ввода,
  длинный ввод и IME, финал с восстановлением и обоими действиями.
- `FoundWordsSectionTest`: параметр `legacy=false/true` сохранён для обоих
  методов. Сохранены пустой список, 146/147 найденных слов, длины групп,
  раскрытие/сворачивание, восстановление прокрутки и групп, статистика,
  длинное неразрывное слово, максимальный установленный уровень с ≥600 словами.
  Второй метод по-прежнему использует v2 fixture в обоих запусках параметра:
  в этой задаче логические параметры не сокращались.
- `LevelsLayoutTest`: открытые/закрытые уровни, сохранённые/все звёзды, обновление
  состояния, выбор уровня, этап 6 и последний уровень. Проверка расположения
  карточек выбирает ветку по фактической ширине `levels_screen` в dp;
  проверка клика выполняется на любой ширине. Production-порог адаптивной сетки
  не менялся, искусственное планшетное окно больше не создаётся.
- `GameLayoutTest`: исходный legacy-экран и все `GameDialog.entries`, задания,
  статистика, текст определения со скобками и переводом строки.
- `ComponentLayoutTest`: сохранён параметр всех десяти компонентов: WELL,
  WORD_INPUT, LETTERS, STARS, FOUND_WORDS, ALERTS, STATISTICS, DEFINITION,
  TOP_BAR, DRAWER; все варианты внутри каждого компонента сохранены.
- `TimeScreenTest`: локальные обновления без refresh, неизвестные/нулевые значения,
  исторический прогресс, Long.MAX_VALUE, все этапы и уровни, загрузка, ошибка,
  недоступная кампания, TalkBack heading и читаемость каждого поля.
- `ComponentInteractionTest`: сохранены все девять методов, включая атрибуцию,
  лицензии, отсутствие утечки ответа в URL, ввод/IME, навигацию и доступность.
- `TextLayoutAssertionsTest`: все шесть сценариев проверки самого assertion-helper:
  кэшированный широкий абзац, многострочный текст, горизонтальное/вертикальное
  обрезание, потерянные строки и ellipsis. Явный `\n` создаёт многострочность
  без фиксированной ширины; синтетические копии TextLayoutResult для проверки
  отказов helper сохранены, constraints UI они не переопределяют.

В остальных androidTest display-параметризации не найдено. Единственные оставшиеся
`Parameterized` — логические параметры legacy/v2 и тип компонента.
Assertions игровой логики, сохранения, лицензий, TalkBack-семантики, переноса
строк и целей 48 dp сохранены. `@Ignore`, `@Disabled` и skip не добавлялись.

## Проверки и ограничения

- `./gradlew :app:compileDebugAndroidTestKotlin --console=plain` напрямую не
  стартовал: у wrapper нет права исполнения. Права файла не менялись.
- `bash ./gradlew :app:compileDebugAndroidTestKotlin --console=plain` — PASS
  (`BUILD SUCCESSFUL`); зависимости задачи также проверили лицензии, собственные
  подсказки и privacy publication.
- Статический просмотр всего `app/src/androidTest` и diff: принудительная ширина,
  подмена плотности/масштаба и display-параметры удалены; число методов `@Test`
  в каждом изменённом классе сохранено.
- Full gate запускает внешний оркестратор после этой задачи; его результат
  здесь не заявляется. Полный `connectedDebugAndroidTest` и отдельные instrumented
  сценарии не запускались по объёму задачи; runtime-прохождение не подтверждено.

Риск: компиляция не подтверждает фактическую раскладку и выполнение assertions
на смартфоне. Искусственные планшетные размеры и увеличенный font scale больше
не входят в эту предрелизную матрицу; поддержка их в приложении сохранена.
Защищённые пути, production, данные, настройки телефона и Git-история не менялись.
