# Загрузка кампании — APP-01 / SHORT15-03

`LevelsRepository.getCampaign()` читает `campaign.json` через `AppContainer`.
Проверенный пакет SHORT15-02 установлен в `data/`, копируется
`syncDictionaryAssets` в assets и упаковывается в APK. `null` остаётся только
для синтетических тестов без v2; ошибка чтения, повреждённый JSON, неизвестный
тип задания и ошибка структурной проверки передаются вызывающему коду; отката
на v1 при ошибке нет.

Формат соответствует выходу генератора: `version`, `countMinLength`, `stages`,
`levels`; задания T1–T7 декодируются в модели `core`. JSON разбирается уже
подключённой kotlinx.serialization, структура проверяется `CampaignValidator`,
производственный профиль — `ProductionCampaignValidator` с ID
`short15-release-v1`.

## Идентичность кампании и миграция прогресса

`LevelsRepository` считает SHA-256 байтов прочитанного `campaign.json` и
помещает его в `Campaign.contentSha256`. Это же значение записано в
`data/manifest.json` как `campaign_source.sha256`, проверяется Gradle-задачей
`verifyDictionaryLicenses` и доступно androidTest через
`BuildConfig.CAMPAIGN_SHA256`. `AppContainer` передаёт ожидаемый хэш в
`LevelsRepository`; asset с другим хэшем отвергается до разбора кампании.

Снимок v2 (`campaignProgressV2`) хранит `campaignId` и диагностический
`resetReason`. Правила миграции:

- **v1 → short15.** Переносятся только ответы слов, которые есть в новой
  кампании. Звёзды пересчитываются заданиями новой кампании; граница
  (`highestUnlockedLevel`) вычисляется `CampaignRules.frontier` только по
  непрерывно пройденным уровням нового порядка. Старые `completed`,
  `finaleReached` и номера уровней не открывают 15-й уровень и не дают финал.
- **v2 без `campaignId`.** Если все ключи сохранения принадлежат текущей
  кампании, снимок принимает её ID, а граница пересчитывается; признаки финала
  сбрасываются, потому что событие финала не восстанавливается по старым флагам.
- **Несовместимый `campaignId`.** Старый v2-снимок копируется в
  `campaignProgressV2Archive` (при повторе — с суффиксом), новый снимок пуст,
  получает новый `campaignId` и `resetReason=campaign-mismatch:…`. Ключи
  отдельного v1-сохранения при этом не удаляются. Это безопасный сброс только
  для несовместимой кампании, а не перенос чужих звёзд.
- **Пустое/повреждённое сохранение.** Пустые ключи дают пустой прогресс без
  выдуманных звёзд. Повреждённый или будущий v2 не заменяется пустым: чтение и
  запись завершаются ошибкой, исходные байты остаются на месте.

Чтение выполняется на IO, разбор, проверка и SHA — на Default. Mutex
объединяет параллельные запросы; успешная кампания и отсутствие файла
кэшируются, ошибки не кэшируются. Конструктор `AppContainer(readCampaign = ...)`
позволяет внедрить синтетическую мини-кампанию или ошибку чтения без замены
производственных ассетов.

`levels.json` и API `getLevels()` остаются историческим v1-стендом для
синтетических тестов 30 уровней. Производственная карта, игра и миграция
используют `getCampaign()`; UI не содержит переключателя сложности.
