# Загрузка кампании — APP-01

`LevelsRepository.getCampaign()` читает необязательный `campaign.json` через
`AppContainer`. `null` означает только отсутствие файла в переходной сборке.
Ошибка чтения, повреждённый JSON, неизвестный тип задания и ошибка структурной
проверки передаются вызывающему коду; отката на v1 при ошибке нет.

Формат соответствует выходу генератора: `version`, `countMinLength`, `stages`,
`levels`; задания T1–T7 декодируются в модели `core`. JSON разбирается уже
подключённой kotlinx.serialization, структура проверяется `CampaignValidator`.
Производственное расписание не навязывается мини-кампаниям. Проверка полной
поставки остаётся обязанностью генератора и независимого аудита.

Чтение выполняется на IO, разбор и проверка — на Default. Mutex объединяет
параллельные запросы; успешная кампания и отсутствие файла кэшируются, ошибки
не кэшируются. Конструктор `AppContainer(readCampaign = ...)` позволяет внедрить
синтетическую мини-кампанию или ошибку чтения без замены производственных ассетов.

Пока v2 не поставлена, существующие экраны используют `getLevels()` и текущие
30 записей `levels.json`. Это отдельный API v1, не преобразование в v2:
счётчики `answers`/`words` независимы, учитывают ответы от 3 букв, следующий
уровень открывается именно по `LevelProgress.completed`. Правила v2 не меняются.
APP-01 не переключает UI и производственные ассеты на новую кампанию.
