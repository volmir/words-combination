# Будущая публикация Git без персональных данных

Это инструкция для владельца и будущих публичных коммитов. Она не переписывает
существующую историю и не меняет текущий remote или глобальный Git-config.

## 1. Что уже нельзя исправить этой задачей

- Старые коммиты содержат личные author-идентичности и исторические ссылки.
  Они остаются в `git log`, pack-файлах, reflog, форках, зеркалах и кэшах
  поисковых систем. Переписывание истории не входило в PRIV-01.
- Текущий `origin` указывает на исторический личный аккаунт. Менять remote без
  решения владельца нельзя.
- Старые APK и архивы вне этого рабочего дерева не отзываются.

## 2. Перед созданием публичного репозитория

1. Владелец выбирает нейтральный проектный аккаунт/организацию и URL. Не
   выдумывать организацию, адрес или контакт.
2. Для новых коммитов задать локально (не глобально) псевдоним проекта:
   ```bash
   git config --local user.name "Составь слова"
   git config --local user.email "<проектный noreply или приватный адрес>"
   ```
   Значение e-mail выбирает владелец. Не коммитить реальный личный адрес.
3. Предпочтительно начать публичную историю с одного чистого коммита или
   отдельного репозитория без старых author-метаданных. Это решение владельца:
   оно меняет историю и поэтому не выполняется автоматически.
4. Проверить `git remote -v`, `git config --local --get user.name`,
   `git config --local --get user.email`, `git log --format='%an <%ae>'`.
5. Перед push прогнать `python3 tools/check_privacy_publication.py --require-generated`
   и `bash orchestrator/run.sh --check full` (в обычной рабочей сессии, не внутри
   автоматического задания).

## 3. F-Droid и релизная карточка

- `AuthorName`, `AuthorEmail`, `AuthorWebSite` необязательны; не заполнять их
  личными значениями. Если нужен контакт, владелец создаёт отдельный проектный
  адрес; PRIV-01 его не придумывает.
- В `SourceCode`/`Repo` указывать только будущий нейтральный проектный URL.
- `License` для собственного кода — MIT; тексты Wiktionary, Kaikki,
  FrequencyWords и Android-библиотек сохранять в notices.
- Не заявлять приватность всей сети интернет: проверяются новый APK, новая
  карточка и новый source repo, а не старые копии.
