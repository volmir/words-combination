# Автоматическая классификация слов — LEX-03

`tools/classify_word_categories.py` дополняет индекс LEX-02 для T6. Уверенные
локальные рубрики сохраняются. ИИ получает только остаточные/неоднозначные
слова: `category=other`, `category_source=unknown:*`. Генерация определений,
проверка разгадываемости и старые циклы `definition`/`guess` не запускаются.
Отчёт не требует утверждения владельца.

## Вход и приоритет проверок

Вход — `category_index.json` от `build_local_definitions.py`. При следующей
штатной локальной сборке экспортируется также `classification_features`:
причина неопределённости (закрытый enum), число пригодных значений и список
рубрик, замеченных локальными правилами в этих значениях. Старый индекс без
этого дополнения поддерживается: число значений неизвестно (`0`), кандидатов
нет. Используйте индекс очищенного игрового словаря, а не список всех статей.

Запрос модели содержит задачу `word-category-v1`, отдельный промпт,
закрытую таксономию из `tools/categories.json`, список `{id, word, features}`.
Произвольные поля в признаках и неизвестные значения запрещены. Тексты статей,
толкования, примеры, формы, родство, URL и сырые пометы в запрос не попадают.
Схема ответа: `{"results":[{"id":"…","category":"tools","confidence":0.95}]}`.
Для каждого входного ID обязателен ровно один результат. Проверяются enum,
конечное число уверенности в `[0,1]`, пропуски, дубли, лишние ID и поля.
Невалидный батч целиком не записывается; предыдущие батчи сохраняются.

ИИ присваивает только рубрику и не может изменять словарь, роли, определения
или их права. Алфавит, нормализация и длина 3–30, доступность роли `target`
(если она экспортирована) проверяются до запроса и при применении. Три запрета
кампании — «прелюбодейка», «брудершафт», «праймериз» — действуют независимо
от рубрики и не попадают в назначения T6, включая локально уверенные рубрики.
Общий ввод этих слов по-прежнему определяется игровым словарём.

По умолчанию результат принимается при `confidence ≥0.8`. Остальные получают
`unknown:ai_low_confidence`; `other` — `unknown:ai_other`. Уверенные результаты
имеют `category_source=ai:codex:<модель>`. Локальные правила не выдаются за ИИ.

## Автоматическое выполнение

Используется уже авторизованный `codex exec`; новый аккаунт и API-ключи не
нужны. Имя доступной в существующей учётной записи модели задаётся `--model`
или `CATEGORY_MODEL`; инструмент не выбирает модель за владельца.
`CATEGORY_MODEL` должна содержать именно имя модели, а не секрет.

```sh
# В окружении задано CATEGORY_MODEL — имя модели существующей авторизации.
python3 tools/classify_word_categories.py \
  --input build/reports/local_definitions/category_index.json \
  --allow-network
```

Без `--allow-network` ни CLI, ни какой-либо сервис не вызывается. Флаг нужен
и для CLI, использующего существующую авторизацию. Файловый транспорт
автоматический: исполнитель получает JSON через stdin и создаёт ответ по
`--output-schema`/`--output-last-message`; ручное редактирование JSON не нужно.
CLI запускается в отдельной временной директории, в `read-only`, без
пользовательской конфигурации и проектных инструкций, shell, поиска и
делегирования. Авторизация CLI сохраняется; настройки пользовательских
провайдеров/MCP в этот вызов не переносятся. Нужна версия CLI с флагами
`--ignore-user-config`, `--ephemeral`, `--output-schema`.
Структурированный вывод описан в
[официальной документации OpenAI](https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex).

Размер батча по умолчанию 20 (предел 1–40), таймаут одного вызова 120 секунд
(1–600), повторов 2 (0–3). Параметры: `--batch-size`, `--timeout`, `--retries`.
Пачки выполняются последовательно. После исчерпания повторов выполнение
останавливается на первом недоступном батче, не отправляя остальные слова.
Возврат `2` означает незавершённую обработку или ошибку, `0` — готовый набор.

При пустом/частичном кэше без доступного исполнителя записываются частичный
снимок, отчёт и `summary.json` с точной командой `resume` (абсолютные пути,
модель, параметры, снимок и явный сетевой флаг). Команда также выводится в
терминал. После восстановления сервиса она продолжает с незавершённых слов.
Завершённые ответы повторно не запрашиваются. Сырые ответы/ошибки сервиса,
ключи и данные авторизации не экспортируются.

## Кэш и точное повторение

Кэш `tools/cache/word_categories/` содержит по одному валидированному решению
на слово. Ключ включает слово и входные признаки, версию задачи, SHA-256
таксономии, промпта и схемы ответа, провайдера и модель. Изменение любого из
этих компонентов не переиспользует старое решение. Каждый файл проверяется
по полному контексту, входу, схеме и собственному SHA-256; конфликт или
повреждение — ошибка, а не молчаливая замена. Запись атомарная.

`build/reports/categories/category_decisions.json` — переносимый снимок
`word-category-decisions-v1`: полный список разрешённых входов, решения,
признак полноты, порог уверенности, контекст с версиями/хэшами и общий SHA-256.
Для воспроизведения сохраняйте его вместе с исходным индексом LEX-02,
таксономией и версией инструментов. Изменённый вход, модель, промпт, таксономия,
порог, дубли или некорректная полнота отклоняются. Частичный снимок тоже
импортируется автоматически и может быть дополнен исполнителем.

```sh
# Без провайдера, авторизации и сетевого флага; модель/порог берутся из снимка.
python3 tools/classify_word_categories.py \
  --input build/reports/local_definitions/category_index.json \
  --snapshot build/reports/categories/category_decisions.json \
  --cache /tmp/category-replay-cache \
  --reports /tmp/category-replay
```

Выходной `category_index.json` содержит итоговые метаданные и пригодные для
T6 рубрики, SHA-256 снимка и исходного индекса, контекст и порог. Последующие
инструменты используют его `categories`. `database_sha256` относится к
исходной БД; `classification.database_categories_updated=false` явно
обозначает отдельный индекс. Этот шаг не пересобирает БД или игровые данные.

## Отчёт CATEGORIES.md и качество

Каждый запуск создаёт `build/reports/categories/CATEGORIES.md` и `summary.json`:

- общее число слов, покрытие для T6, количество незавершённых решений;
- числа и доли по источникам `rules`, `ai`, `ai_unresolved`, `unknown`,
  отдельно вклад каждого источника в покрытие относительно всего словаря;
- количество слов и до 20 примеров для каждой рубрики;
- список пригодных для T6 категорий с ≥40 словами;
- детерминированную диагностическую выборку до 300 слов;
- SHA-256 снимка, порог, при необходимости команду возобновления.

Ориентиры — покрытие **≥35%** и точность **≥90%**. Это цели, а не заявленные
достигнутые метрики. В исходной поставленной БД на момент LEX-03 все 23 393
слова имеют `other`; это не результат нового ИИ-пути. Настоящие счётчики
нового набора появляются в отчёте после его обработки. Оценку уверенности
модели нельзя выдавать за измеренную точность.

Без независимой разметки отчёт пишет «точность не измерена», размер 0.
Для измерения укажите `--gold /путь/independent_labels.json`:

```json
{"schema":"word-category-gold-v1","independent":true,"annotator":"отдельный-разметчик","labels":{"образец":"other"}}
```

Разметка должна быть создана независимо от проверяемых решений, не копированием
ответов этой модели. Флаг `independent` — заявление происхождения разметки,
инструмент проверяет её структуру, слова и enum. Отчёт показывает размер,
долю точных совпадений и SHA-256 разметки; для ИИ — отдельную точность и её
размер (или отсутствие проверенных решений ИИ). Непустая выборка сама по себе
не доказывает её репрезентативность для всего словаря.
