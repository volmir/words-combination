# Редакторский экспорт кампании short15

Документ описывает воспроизводимую выгрузку текущей кампании из `data/` и
порядок ручной правки книги `CAMPAIGN_REVIEW_15.xlsx`. Экспорт только читает
установленные данные: `data/campaign.json`, `data/words.txt`,
`data/definitions.db` и `data/manifest.json`. Он не меняет игру, не ходит в
сеть, не использует ИИ и не пишет в `data/`.

## 1. Команда экспорта

Из корня проекта:

```bash
python3 tools/campaign_review_export.py \
  --root . \
  --output build/reports/curation/curation_snapshot.json
```

Можно указать каталог вместо файла — тогда JSON будет называться
`curation_snapshot.json`:

```bash
python3 tools/campaign_review_export.py --output build/reports/curation
```

Отдельный каталог для таблиц задаётся через `--catalog-dir`. Запись в `data/`
запрещена и завершается ошибкой.

Экспорт формирует машинный JSON и человеческие CSV/TSV:

| Файл | Содержимое |
|---|---|
| `curation_snapshot.json` | Полный снимок: SHA входов, права, 15 уровней, 49 заданий, все собираемые слова, подсказки и пустой шаблон правок |
| `levels.csv` / `levels.tsv` | Уровень, этап, исходник, R/M, число собираемых слов, категория исходника |
| `tasks.csv` / `tasks.tsv` | Все 49 заданий: тип, условие, буква/окончание/минимальная длина, порог `n`, назначенные и пересчитанные цели |
| `answers.csv` / `answers.tsv` | По строке на пару «уровень — собираемое слово»: длина, число уровней повтора, роли T1–T7, категория и источник категории, число толкований |
| `hints.csv` / `hints.tsv` | Для целей T3/T4/T6: исходное толкование, безопасный вариант с `***`, источник и признак пригодности |
| `short_repeats.csv` / `.tsv` | Повторяемость коротких слов (3–4 буквы) по всем уровням |
| `short_repeats_adjacent.csv` / `.tsv` | Повторы в соседних парах уровней |
| `edits.csv` / `edits.tsv` | Пустой шаблон листа «Правки»: строки привязки без действий |

CSV/TSV читаются стандартной библиотекой Python (`csv`) и не требуют Excel.
Excel-книга — только удобное представление; источником истины остаются JSON и
таблицы.

## 2. Что фиксирует JSON

- `snapshot.inputs` — SHA-256 четырёх установленных входов.
- `snapshot.campaign_id` — сведения `manifest.campaign_source`, включая профиль,
  число уровней, число звёзд и SHA кампании.
- `snapshot.definitions_rights` — блок `manifest.definitions` без изменений.
- `snapshot.rights` — пересчитанные по базе факты: число определений
  `wiktionary`/`own`, фактическое покрытие, `audit.passed`,
  `rights_review.passed`, политика прав. `publication_allowed` всегда `false`,
  пока ручной аудит и проверка прав не пройдены.
- `overview`, `tasks`, `answers`, `hints`, `short_repeats`, `edits` — каталоги
  в стабильном порядке.
- `tasks[].recounted_targets` — независимый пересчёт по установленному словарю и
  базе: для T3 все законные длинные ответы, для T4 пересечение назначенных
  целей с собираемыми словами, для T6 полный локальный набор подтверждённой
  категории.

Все числа и хэши вычисляются из файлов. В вывод не попадают абсолютные пути,
ключи, токены и другие секреты. Повторный запуск на тех же входах даёт тот же
JSON и те же CSV/TSV.

## 3. Книга `CAMPAIGN_REVIEW_15.xlsx`

Книга лежит в корне проекта. Основной лист для редактора — **«Правки»**.
Остальные листы (`Обзор`, `Задания`, `Подсказки`, `Лицензии`,
`Уровень 01`…`Уровень 15`) нужны только для чтения и проверки.

На листе «Правки» девять колонок:

| Колонка | Поле | Правило |
|---|---|---|
| A | Уровень | Привязка к снимку, не менять |
| B | ID задания | Привязка к снимку, **ID редактировать запрещено** |
| C | Тип | Привязка к снимку, не менять |
| D | Текущее слово | Старое слово цели/подсказки; для `T6_ADD` пусто |
| E | Действие | Одно из действий ниже; пусто = без изменений |
| F | Новое значение | Новое слово, число, текст подсказки |
| G | Основание | Обязательное объяснение, почему правка нужна |
| H | Права/статус | Известный статус источника или `не подтверждено` |
| I | Источник/URL | Ссылка или иной проверяемый источник основания |

Редактируются только E–I. Строки A–D — идентичность снимка; их изменение
должно приводить к отказу импорта. Для новых строк заполняются A–D (уровень,
ID существующего задания, тип, пустое старое слово), затем E–I.

### Действия

| Действие | Что заполнить | Смысл |
|---|---|---|
| `T6_ADD` | D пусто, F — новое слово, G — основание, I — источник | Предложить добавить слово в T6. Проверяются словарь, составимость и наличие определения; неверная категория не подменяется |
| `T6_REMOVE` | D — существующее слово T6, F пусто | Удалить ровно одно слово из списка T6 |
| `SET_N` | F — целое `n` | Изменить порог задания T1/T2/T6/T7; проверяется достижимость |
| `SET_R` | F — целое `R` | Изменить порог уровня; проверяется `1 ≤ R ≤ M` |
| `T4_SWAP` | D — старая загадка, F — новая | Заменить одну цель T4; проверяются составимость, частота, подсказка и уникальность |
| `T3_SWAP` | D — старый `hintTarget`, F — новый | Заменить ориентир T3; проверяются длина, составимость и уникальность |
| `HINT_REPLACE` | D — слово, F — новый текст | Предложить безопасную подсказку; она сохраняется только в pending-файл и не меняет `definitions.db` или права |

Пустое действие означает «изменений нет». Пустая книга не меняет исходную
кампанию: импорт должен дать ноль изменений и кандидат, побайтно совпадающий
с `data/campaign.json`.

## 4. Новая профессия для T6

Слово может существовать в `data/words.txt` и собираться из исходника, но его
категория в `data/definitions.db` может быть `other`, `sport`, `health` или
другой. Например, спортивное слово не становится профессией только потому,
что редактор считает его подходящим по смыслу. Категория — это отдельное
свидетельство в базе, а не свойство слова в игре.

Поэтому `T6_ADD` — предложение, а не назначение категории:

1. Заполните D пустым, F — словом, G — редакторским основанием, I — ссылкой
   на источник, где слово действительно описано как профессия/занятие.
2. Если текущая категория слова не `professions`, импорт обязан выдать флаг
   `manual_category_evidence_required`. Это не ошибка словаря и не разрешение
   молча переписать категорию.
3. Подтверждение категории требует отдельного редакторского свидетельства.
   Нельзя использовать ИИ-разметку, догадку или «звучит как профессия» вместо
   источника.
4. Даже подтверждённое слово должно быть собираемым из исходника и иметь
   пригодную подсказку. Порог `n` не уменьшается автоматически.

Текущий T6 уровня 14 (`l14-t6`) содержит шесть кандидатов при `n=5`, поэтому
одно спорное слово необязательно. Не превращайте редкие исторические названия
в обязательные только ради заполнения списка.

## 5. Четыре разных понятия

| Понятие | Где живёт | Что означает |
|---|---|---|
| Слово словаря | `data/words.txt` | Слово можно ввести и составить из букв исходника; ещё не значит, что оно подходит по теме |
| Тема T6 | `word_metadata.category` в `data/definitions.db` | Проверенная категория, например `professions`; ключ, а не подпись |
| Определение | таблица `definitions` в `data/definitions.db` | Исходный текст и источник; в подсказке маскируется, но в базе не переписывается |
| Права | `manifest.definitions.audit` и `rights_review` | Юридический/редакторский статус; не становится `true` от качества текста или сборки |

Редакторская правка кампании не даёт прав на определение и не меняет лицензию.
`HINT_REPLACE` — только предложение в pending-файл; полный текст и атрибуция
основной базы остаются прежними до отдельного решения владельца.

## 7. Границы задачи

Экспорт не выполняет GEN/LEX/SEL, не меняет уровни, слова, пороги, категории и
права, не применяет правки из книги. Импорт правок и установка кандидата —
отдельные задачи. До отдельного решения владельца `data/` остаётся неизменной,
а `audit.passed`/`rights_review.passed` не выставляются в `true`.
