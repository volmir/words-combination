# FDROID-REPRO-02: обязательный выпускной гейт

**Состояние: IMPLEMENTED / AWAITING OWNER VALIDATION.** Скрипт и офлайн-тесты
подготовлены; для будущего тега `1.0.2` реальная проверка с ключом владельца
ещё не выполнялась. Публикация, tag push и отправка в F-Droid не разрешены
этим документом.

## Что подтверждено ранее

18.11.2026 владелец самостоятельно проверил исходники тега `1.0.1`:

- две неподписанные сборки в разных чистых каталогах дали побайтно одинаковые
  `classes.dex` и `assets/dexopt/baseline.prof`;
- две последовательные неподписанные сборки в одном полноценном Git-клоне дали
  побайтно идентичный APK;
- новая подписанная и неподписанная пара из этого клона прошла
  `apksigcopier compare --unsigned` (`LOCAL_REPRODUCIBILITY=PASS`);
- **опубликованный ранее** APK `1.0.1` этим методом **не воспроизводится**:
  он отличается по `classes.dex` и `baseline.prof` и не должен использоваться
  как доказательство воспроизводимости.

Проверка F-Droid buildserver не проводилась. Результаты выше приведены со слов
владельца; файлы APK и приватный ключ не включаются в Git.

## Контракт кандидата 1.0.2

| Проверяемое условие | Значение |
| --- | --- |
| `versionName` | `1.0.2` |
| `versionCode` | `3` (больше, чем `2` у `1.0.1`) |
| Git | локальный аннотированный тег `1.0.2` на уже утверждённом коммите |
| Публичный сертификат SHA-256 | `a10cdd4ff4000673f14db9fe4a814f8bbd63b6e2007f5f38b1fe5cfb7310f353` |
| Имя APK | `WordsCombination-v1.0.2.apk` |
| Результаты | `SHA256SUMS.txt`, `reproducibility-evidence.json` |

Код приложения, словарь, кампания, лицензии, `applicationId`, настройки
R8 и Baseline Profiles остаются без изменений. Повышение версии само по себе
не является разрешением на публикацию.

## Ручной запуск перед публикацией

Нужны Linux/macOS с Bash, JDK 21, Android SDK, Python 3, `git`,
`apksigcopier` и `apksigner`. Запускать на компьютере владельца — **не в CI**,
поскольку только он располагает закрытым release-ключом.

1. Слить проверенный PR и обновить локальную `main`. Убедиться, что дерево чистое.
2. Создать **локальный** аннотированный тег только на проверенном коммите.
   **Пока не отправлять его на GitHub.**
3. Использовать четыре ранее настроенные и **экспортированные** переменные
   `SOSTAVSLOVA_RELEASE_*`. `SOSTAVSLOVA_RELEASE_STORE_FILE` должен быть
   абсолютным путём к существующему keystore за пределами репозитория.
4. Запустить гейт.

```bash
cd ~/www/words-combination
git pull --ff-only
git status --short
git tag -a 1.0.2 -m 'Words Combination 1.0.2'

python3 tools/prepare_verified_release.py \
  --tag 1.0.2 \
  --expected-version-code 3
```

Если тег уже существует, проверить его и **не переназначать**. Если в `git
status --short` есть изменения, сначала разобраться с ними. Тег создавать
только после утверждения PR и ручной проверки готовности кандидата.

**Что делает скрипт:**

1. Проверяет существование аннотированного тега и четырёх полей подписи.
2. Создаёт **первый полноценный Git-клон** тега во временном каталоге.
   `git worktree` не используется: Android Gradle Plugin может записать
   `NO_VALID_GIT_FOUND` вместо Git-ревизии.
3. Собирает неподписанный APK с удалёнными переменными подписи, сохраняет
   результат и удаляет **только временный клон**. Затем заново клонирует тот же
   тег **по точно такому же абсолютному пути** и независимо собирает
   подписанный APK. Это необходимо, поскольку AGP может включать абсолютный
   путь клона в `version-control-info.textproto`, что мешает побайтовому
   сравнению сборок из разных каталогов. Секреты получает только подписанная
   Gradle-сборка. Обе используют `--no-build-cache --no-daemon`.
4. Проверяет версии обоих APK, SHA-256, v2-подпись, **точный публичный
   сертификат владельца** и `apksigcopier compare --unsigned`. Используется
   существующая проверка `tools/verify_reproducible_release.py`.
5. **Только после успешного сравнения** копирует APK, `SHA256SUMS.txt` и
   локальное JSON-свидетельство в новый каталог:

```text
app/build/outputs/verified-github-release/1.0.2/
    WordsCombination-v1.0.2.apk
    SHA256SUMS.txt
    reproducibility-evidence.json
```

При любой ошибке скрипт прекращает работу и **не экспортирует готовые
артефакты**. Уже существующий каталог назначения он не перезаписывает.
Временные клоны создаются вне исходников и автоматически очищаются.

Логи не должны содержать секретов. Не использовать `set -x`, `--debug`,
публикацию env или передачу паролей в аргументах команд. Скрипт не создаёт
ключи, теги, коммиты, GitHub Releases и не делает push.

## Проверка результата и публикация

Если скрипт завершился с кодом 0, вывод содержит
`LOCAL_SOURCE_TO_SIGNED_APK_VERIFIED`, commit тега, версию и SHA-256.
Свидетельство подтверждает **локальную проверку двух последовательных
независимых клонов**, но не
проверку инфраструктурой F-Droid.

Дополнительно можно выполнить штатную задачу Gradle, которая теперь **не
создаёт новый APK**, а требует локальный PASS-отчёт, совпадение версии,
коммита тега, сертификата и контрольной суммы уже проверенного файла:

```bash
bash ./gradlew :app:prepareGithubRelease --console=plain
```

Без успешного запуска Python-гейта задача завершится ошибкой.

После отдельного разрешения владельца на публикацию:

```bash
cd ~/www/words-combination
cd app/build/outputs/verified-github-release/1.0.2
sha256sum -c SHA256SUMS.txt
```

Затем из корня репозитория можно отправить **проверенный** тег `1.0.2` и
создать GitHub Release с двумя артефактами: `WordsCombination-v1.0.2.apk`
и `SHA256SUMS.txt`. `reproducibility-evidence.json` предназначен для
внутреннего аудита, а не для публичного списка файлов релиза.

Задача `:app:prepareGithubRelease` только повторно проверяет имеющееся
свидетельство, сама не создаёт независимую сборку. Публиковать только файлы из
`verified-github-release/1.0.2/`.

После публикации F-Droid metadata/recipe должны указывать на **этот же**
`versionCode=3`, тег и опубликованный APK. Проверка на F-Droid buildserver,
сканер лицензий и решение сопровождающих остаются отдельными требованиями.

Старые теги и GitHub Releases `1.0.0` и `1.0.1` **не менять**.
