# Воспроизводимая сборка собственных подсказок

`data/definitions.db` — утверждённый артефакт в Git. Текущий SHA-256:
`73d09ac2d445ad7f4c30226248b30769d6e46bd6858a8907750d16561b258d7d`.
Он связан с `data/manifest.json` и ручным аудитом. Для debug и androidTest
используется тот же артефакт и тот же строгий gate.

## Подготовка чистой среды, включая экспорт в AI Studio

Обычный полный checkout содержит БД. Если экспорт пропустил бинарные файлы,
проверка сначала пытается восстановить отсутствующую БД из закреплённого
Git-коммита. Если Git-истории нет, либо системная SQLite отличается от
закреплённой, выполните явную подготовку с разрешённой сетью:

```bash
python3 tools/prepare_owned_hints.py --download
python3 tools/build_owned_hints.py --check
bash ./gradlew :app:assembleDebug :app:assembleDebugAndroidTest --console=plain
```

Подготовка скачивает утверждённую БД, только если она отсутствует и недоступна
в Git, и пакет библиотеки SQLite из Ubuntu Security. URL привязаны к версии
пакета и полному Git-коммиту; SHA-256 обоих файлов закреплены в
`tools/owned_hints_toolchain.json`. Перед публикацией восстановленной БД
проверяются её SHA и соответствие manifest. Существующая изменённая БД не
заменяется. Документы владельца, аудит и manifest не редактируются.

Без `--download` инструмент работает только с локальными файлами и Git.
Обычный `--check`, Gradle и worker ничего не скачивают. После подготовки
сборка подсказок не требует сети. Это не распространяется на загрузку
зависимостей самого Gradle при первом запуске.

## Что закреплено

Исходная проверенная среда: Python 3.10.12, SQLite 3.37.2, Ubuntu-пакет
`libsqlite3-0_3.37.2-2ubuntu0.8_amd64.deb`. Lock хранит SHA пакета и самой
библиотеки, SQLite source id и хэш полного набора compile options.

Если библиотека системного Python имеет тот же source id, версию и compile
options, используется существующий генератор напрямую. Иначе он исполняется
тем же Python в дочернем процессе, где `LD_LIBRARY_PATH` указывает только на
проверенную библиотеку из `.local/owned-hints-toolchain/lib/`. Worker повторно
проверяет профиль SQLite перед записью. Системные библиотеки не заменяются;
SQLite CLI из Android SDK на этот выбор не влияет.

Генератор SQL, порядок данных и побайтное сравнение свежего rebuild с manifest
сохранены. Другой SHA, неподходящая библиотека, повреждённый кэш или ошибка
worker завершают проверку ошибкой. Совпадение логического содержимого не
заменяет совпадение байтов и не переносит аудит на другую БД.

Для переносимого worker поддерживается Linux x86_64 с glibc >= 2.34,
Python 3.10+ с модулем `sqlite3`. Подготовка пакета требует `dpkg-deb` и
HTTPS-доступа при `--download`; Docker и root не нужны. Совместимость
конкретного Python подтверждается worker и итоговым rebuild, а не одним
номером версии. Другие архитектуры без совпадающей нативной SQLite требуют
отдельного проверенного toolchain; автоматической подмены нет.
