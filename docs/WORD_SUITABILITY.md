# Пригодность слов для кампании (LEX-04)

`tools/assess_word_suitability.py` — отдельная задача того же авторизованного
Codex CLI, который используется LEX-03. Провайдер, пакетный транспорт,
валидация кэша, таймауты, ограниченные повторы и офлайн-снимки общие;
задача, промпт, схема ответа и пространство кэша отдельные.
Модель задаётся `--model` или прежней переменной `CATEGORY_MODEL`.
Новые аккаунты, зависимости, экраны и ручное утверждение не требуются.

## Вход

Генератор передаёт JSON `word-suitability-input-v1`, массив `candidates`.
Одна запись на сочетание нормализованного слова и роли; для двух оценок
нужны две записи с ролями `source` и `target`. Пример синтетического входа:

```json
{
  "schema": "word-suitability-input-v1",
  "candidates": [{
    "word": "образец",
    "role": "target",
    "features": {
      "noun": true,
      "role_decision": "review",
      "reachable": true,
      "frequency": 2,
      "freq_rank": 90000,
      "labels": []
    }
  }]
}
```

`noun` — подтверждённое существительное; `role_decision` — `keep`, `review`
или `exclude` из лексического отбора для данной роли (LEX-01).
`reachable` — результат проверки ограничений назначения: для исходника
выполнимость заданий, для цели составимость и допустимость назначения.
`null` означает отсутствие проверки; модель не может подтвердить достижимость.
`frequency` — наблюдаемая частота словоформ FREQ-01, не оценка ИИ;
`freq_rank` — положительный ранг либо `null` при отсутствии наблюдений.
`labels` — отсортированный уникальный список из закрытого набора `LABELS`
в модуле; пометы относятся к рассматриваемому употреблению слова.
Тексты статей, определения, цитаты, источники и произвольные строки
не допускаются: посторонние поля и значения отвергаются до вызова провайдера.
Оценка пригодности определения остаётся отдельной задачей HINT.

## Приоритет и результат

1. Три запрета владельца действуют для обеих ролей независимо от частоты
   и ответа модели: прелюбодейка, брудершафт, праймериз.
2. Не-существительное, исключённая роль, жёсткая помета (`offensive`,
   `proper_name`, `productive_diminutive`), длина вне границ роли или
   недостижимость дают `unsuitable`. Границы исходника 8–13, цели 3–30.
   Непроверенная достижимость даёт `insufficient_data`.
3. Хлопкопункт, реввоенсовет и селитроварня сохраняются как предпочтительные
   исходники после ограничений пункта 2. Это разрешает низкую частоту и
   историческую помету исходника, но не распространяется на роль цели.
   Закрытый набор обхода: `rare`, `historical`, `obsolete`, `restricted_usage`,
   `abbreviation`, `specialist`; иная лексическая неуверенность оценивается отдельно.
4. Нейтральное слово с `role_decision=keep`, частотой ≥100 и рангом ≤30000
   принимается дешёвым правилом. Это версионированная эвристика узнаваемости
   для назначения, а не новое правило включения слова в общий словарь.
5. Остальные случаи обрабатываются автоматически пакетами ИИ. Ответ:
   `suitable` (пригодно), `unsuitable` (непригодно), `insufficient_data`
   (недостаточно данных), короткая причина и `assessment_version`.
   Неуверенность или отсутствие ответа исключает слово из пула назначений.
6. `ranked_pools` разрешает ничьи детерминированно: предпочтение владельца
   только для исходников, затем наблюдаемый ранг, затем слово по алфавиту.

`word_suitability.json` хранит входные признаки отдельно от оценки,
`assessment_source` (`rules`, `ai`, `pending`), версию, хэш оценки и два пула.
Только `suitable` попадает в соответствующий пул. Запреты и ограничения
повторно применяются при сборке результата, даже при конфликте с моделью.
Обычный допустимый ввод и словарь не изменяются. Потребители профилей и
кампании используют эти пулы в последующих заданиях; LEX-04 не генерирует кампанию.

## Выборочный режим

Без `--pairs-file` работает прежний полный проход по всем парам входа. С этим
флагом оцениваются только явно перечисленные пары; остальные слова не
отправляются модели и не получают решения. Формат файла: UTF-8, по одной паре
`слово роль` в строке, пустые строки и `#`-комментарии игнорируются. Роль —
`source`/`исходник` или `target`/`цель`; слово нормализуется (ё→е). Повтор пары
схлопывается, отсутствующая во входе пара — ошибка, а не молчаливый пропуск.
Пустой файл — корректный no-op без обращений к модели.

Порядок решения не меняется: жёсткие запреты, роль, длина, составимость,
структурные пометы и частоты; затем совместимый кэш для **этой роли**; только
после этого — ИИ для оставшихся пар. `--max-new-decisions`, `--max-batches` и
`--time-budget` ограничивают новые обращения; в кэш попадают только полностью
проверенные ответы. Без сети или при исчерпанном бюджете незавершённая пара
остаётся `insufficient_data`/`pending` и не становится `suitable`.
`--snapshot` в выборочном режиме переносит только точно совпавшие по слову,
роли, признакам, политике, провайдеру и модели элементы — полный или уже
выборочный снимок можно использовать как источник частичных решений.

`summary.json` содержит режим, число запрошенных/выбранных пар и счётчики
`rule_decided`, `cache_hit`, `ai_new`, `unresolved` отдельно для `source` и
`target`. `unresolved` учитывает пары без ответа и завершённые
`insufficient_data`: пригодность не установлена. Повторный вызов с тем же
входом и кэшем не создаёт новых запросов.
Смена роли, признаков, модели, провайдера, промпта, политики или схемы
инвалидирует ключ; решения разных провайдеров не смешиваются.

Потребители: `pick_level_words --suitability` принимает полный результат как
раньше, а для `mode=selective` допускает подмножество пар; недостающие пары
остаются `pending` и не разрешают назначение. T4 требует цель с полезной
маскированной подсказкой; T3 использует как `hintTarget` только слово с такой
подсказкой, хотя звезда по-прежнему даётся за любой подходящий ответ длины L+.
T6 проверяет только явное тематическое множество уровня и не зависит от
выборочной пригодности фоновых слов. Обычный ввод в приложении по-прежнему
проверяется общим словарём без обязательной оценки каждой единицы.

## Запуск и возобновление

```sh
python3 tools/assess_word_suitability.py \
  --input build/suitability_input.json --model "$CATEGORY_MODEL" --allow-network
```

Выборочный проход по явным парам с ограничением новых решений:

```sh
python3 tools/assess_word_suitability.py \
  --input build/suitability_input.json \
  --pairs-file build/requested_pairs.txt \
  --max-new-decisions 40 --max-batches 2 --time-budget 600 \
  --reports build/reports/suitability-selective \
  --model "$CATEGORY_MODEL" --allow-network
```

Сеть разрешает только явный `--allow-network`; без него CLI провайдера
не запускается. Размер пакета 1–40 (по умолчанию 20), таймаут 1–600 секунд
(120), повторы 0–3 (2). Весь ответ пакета проверяется до записи решений;
невалидные enum, версия, ID, пропуски, дубли и лишние поля отклоняются.
При отказе сохраняются уже завершённые пакеты; повтор той же команды
продолжает только незавершённые записи. Код выхода 2 обозначает ошибку
или незавершённую обработку; корректный ответ `insufficient_data` считается
завершённым решением, но не разрешает назначение.

Готовый снимок переносится вместе с входом и позволяет работать без
провайдера и его авторизации, включая свежий кэш:

```sh
python3 tools/assess_word_suitability.py \
  --input build/suitability_input.json \
  --snapshot build/reports/suitability/suitability_decisions.json
```

Модель берётся из снимка, если не указана явно. Вход, роль, каждый признак,
политика, задача, промпт, схема, провайдер и модель участвуют в проверке
совместимости. Изменение признаков инвалидирует соответствующий кэш;
старый снимок отклоняется, а не выдаётся за актуальную оценку. При новом
входе запускайте команду без старого `--snapshot`: неизменившиеся решения
подхватятся из кэша. В выборочном режиме снимок может быть полным или
частичным: переносятся только элементы с точным совпадением слова, роли,
признаков и контекста, остальные пары остаются нерешёнными. Снимок можно
читать и перезаписывать по одному пути. Снимки и отчёты создаются
автоматически, ручное редактирование не требуется.

Проверка на синтетике: `python3 -m unittest discover -s tools/tests -p 'test_word_suitability.py'`.
Живая модель и реальный набор в рамках LEX-04 не запускались; точность её
оценок этими тестами не измеряется.
