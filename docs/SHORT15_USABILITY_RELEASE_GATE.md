Дата: 2026-11-15. Работа выполнена в рабочем дереве без commit/push.

## 3. P1 — очевидная неясность (исправлено)

### P1-1. Ряд звёзд на карте назывался «Задания»

**Воспроизведение.** Включить TalkBack, открыть карту, сфокусировать карточку
уровня. Озвучивалось «… Задания, Получено 0 из 1 звезды». На карте нет
действия «Задания»; это только прогресс звёзд.

**Код.** `StarsRow.kt` всегда подставлял `R.string.tasks`; `LevelsScreen.kt`
использовал этот ряд только для чтения.

**Исправление.** У `StarsRow` появился необязательный `label`; карта передаёт
`level_stars_label` — «Звёзды». Кликабельный ряд в игре по-прежнему
называется «Задания», потому что открывает задания.

**Тест.** `LevelsLayoutTest` проверяет `hasContentDescription("Звёзды")` и
отсутствие «Задания» на карте. Устройство **NOT RUN**.

### P1-2. Исходное слово читалось по одной букве

**Воспроизведение.** Включить TalkBack на экране игры. Свайп по плиткам
давал N отдельных узлов: «Ч», «Е», «М», …; слово не озвучивалось как слово.

**Код.** `LetterTiles.kt` рисовал отдельные `Text` без объединяющей семантики.

**Исправление.** Плитки объединены в один узел с описанием
«Исходное слово: <слово>» (`source_word_description`). Визуально плитки не
изменились, новые эффекты не добавлялись.

**Тест.** `ComponentInteractionTest.sourceWordIsAnnouncedAsOnePhraseInsteadOfSeparateLetters`.
Устройство **NOT RUN**.

### P1-3. Пустой/латинский ввод молча ничего не делал

**Воспроизведение.** Открыть уровень, ввести `abc`, `123--` или пробелы,
нажать Done/«Проверить». Баннера нет, счётчик не меняется — кнопка выглядит
сломанной. Причина: `Alphabet.normalize` выбрасывает латиницу/цифры, `GameState`
возвращает `EMPTY`, а `GameViewModel` на `EMPTY` делал `return`.

**Код.** `GameViewModel.onSubmit`, ветка `AnswerResult.EMPTY`.

**Исправление.** До записи в DataStore проверяется нормализованный ввод; для
пустого результата показывается `answer_empty` — «Введите слово русскими
буквами» (`AlertType.Danger`). Ввод не очищается, чтобы его можно было
исправить. Ветка `EMPTY` после транзакции также больше не молчит.

**Тест.** `GameViewModelTest.emptyOrNonRussianSubmissionExplainsItselfAndLongInputIsKeptWhole`
(сообщение, сохранённый ввод, отсутствие записи). Устройство **NOT RUN**.

### P1-4. Подсказка появлялась без объявления TalkBack

**Воспроизведение.** Включить TalkBack, нажать «Подсказка». Текст появляется
выше кнопки, фокус остаётся на кнопке; без live-region пользователь не узнаёт,
что подсказка пришла.

**Код.** Оба блока `game_hint` в `GameScreen.kt` не имели `liveRegion`.

**Исправление.** Оба блока (обычная подсказка и лестница кампании) помечены
`LiveRegionMode.Polite`. Это семантика доступности, не звук/анимация
приложения.

**Тест.** `CampaignGameUiTest.accumulatedHintStepsCostAndZeroBudgetAreVisible`
проверяет `LiveRegionMode.Polite`. Устройство **NOT RUN**.

### P1-5. Устаревшие ожидания connected-тестов (регрессионный гейт, не UX)

При статической сверке обнаружены тесты, которые не соответствуют текущим
строкам и кампании. На устройстве они бы упали, хотя приложение работает:

- `GameNavigationTest` и `MainScenariosUiTest` ожидали «Слово … не найдено!»;
  текущий отказ — «Слово «…» не распознано словарём». В качестве неизвестного
  слова использовалось «пар»; в полном словаре оно даёт отказ по буквам, а не
  `NOT_FOUND`. Заменено на заведомо отсутствующее `щщщ` и текущий текст.
- Оба теста искали кнопку «Показать подсказку» в кампании; у кампании кнопка
  «Подсказка · цена …». Поиск заменён на стабильный `game_hint_button`.
- `ComponentInteractionTest` ожидал старую фразу «литературные примеры не
  включены»; в `strings.xml` действует «Литературные примеры исключены».

Это не ослабление: проверки стали соответствовать фактическому контракту
строк и реальному словарю. Тесты **скомпилированы**, но на устройстве
**NOT RUN**; см. §8.

## 5. Статическая доступность

### 5.1. Интерактивные цели 48 dp

| Элемент | Реализация | Статус |
|---|---|---|
| Верхняя панель (меню/назад) | `IconButton` + `size(48.dp)` | OK по коду |
| Пункты меню | `Surface(onClick)` + `heightIn(min = 48.dp)` | OK |
| Карточки уровней, «Продолжить», «Повторить» | `OutlinedButton` + `heightIn(min = 48.dp)` | OK |
| Кнопка «Проверить» | `Button` + `heightIn(min = 48.dp)` | OK |
| Ссылки найденных слов | `sizeIn(minWidth = 48.dp, minHeight = 48.dp)` | OK |
| Ряд звёзд в игре | `sizeIn(48.dp)` + `clickable` | OK |
| «Задания · N из M», группы найденных слов, «Закрыть» | `TextButton` + `heightIn(min = 48.dp)` | OK |
| Кнопки диалогов welcome/финал/выход/закрытый уровень | `TextButton` Material 3; минимальная интерактивная область M3 — 48 dp | OK по коду; приборно **NOT RUN** |
| Действия игры «Подсказка», «Статистика», «Задания» | `OutlinedButton` + `heightIn(min = 48.dp)` | OK |

Тесты `GameLayoutTest`, `LevelsLayoutTest` и `ComponentLayoutTest` проверяют
`hasClickAction()` и размер не меньше 48 dp на 320/360 dp и 100/200%;
они скомпилированы, но на устройстве **NOT RUN**. Отдельного P0/P1 по 48 dp
в коде не найдено.

### 5.2. TalkBack

- Карточка уровня: номер и слово, статус, «Звёзды», `stateDescription`
  «Получено N из M звёзд», рекомендация, замок/корона. После P1-1 «Задания»
  на карте больше не читается.
- Исходное слово: одна фраза «Исходное слово: …» после P1-2.
- Поле ввода: `contentDescription = "Ваш ответ:"`, текст остаётся
  `EditableText`; кнопка «Проверить» — обычная текстовая кнопка.
- Задания, загадки, найденные группы, статистика и подсказки — текстовые узлы;
  подсказка объявляется как live region после P1-4.
- Ошибки и успех — `AlertBanner` с `LiveRegionMode.Polite`; текст не обрезается.
- Диалоги — платформенные `Dialog`/`AlertDialog`; заголовки и кнопки читаются,
  закрытие возвращает фокус на экран. `testTag` в озвучивание не попадает.
- `R.string.source_word_description`, `R.string.level_stars_label`,
  `R.string.answer_empty` добавлены в `strings.xml`; литералов в коде нет.

### 5.3. IME и клавиатура

- `KeyboardOptions`: без автокоррекции, `KeyboardCapitalization.None`,
  `hintLocales = ru`, `ImeAction.Done` в игре и `Search` в поиске значения.
- `KeyboardActions` отправляет ответ по Done/Go/Search/Send/Next; кнопка и IME
  используют один `onSubmit`; после отправки фокус остаётся в поле.
- `imePadding()` + `verticalScroll`; поле и кнопка доступны при клавиатуре;
  на 320 dp/200% поле переходит в вертикальную раскладку.
- В игре нет скрытого обрезания ввода (UXF-01), поэтому длинный ответ не
  теряет последние символы. Пустой/латинский ввод теперь объясняется (P1-3).
- Ручная проверка IME и автокоррекции — **NOT RUN**.

### 5.4. Пустые и переполненные состояния

- Карта: загрузка без ложных карточек; ошибка + «Повторить»; пустая карта не
  подменяется фиктивными уровнями; приветствие ждёт готовой непустой карты.
- Игра: загрузка, ошибка старта, сохранение, «все слова найдены», пустой
  список найденных, отсутствие определения, исчерпанный бюджет подсказок.
- Длинные тексты: баннеры в потоке под полем, `heightIn(min = 48.dp)` только
  резервирует место, но растёт по контенту; задания/статистика/диалоги
  прокручиваются.
- Ограничения: на 320/360 dp и 200% всё это проверено только статикой и
  layout-тестами; устройство **NOT RUN**.

### 5.5. Диалоги, возврат и черновик

- Welcome, закрытый уровень, финал, статистика, задания, определение и выход
  имеют `onDismissRequest`/Back; системный Back в игре возвращает на карту;
  на карте двойной Back — выход через диалог.
- Черновик хранится в `SavedStateHandle`; поворот и process death его
  сохраняют. После явного Back на карту создаётся новый экран, поэтому
  неотправленный черновик не переносится — это P2-1, не потеря прогресса.
- Финал восстанавливается из DataStore и не повторяется после закрытия;
  ответы и звёзды сохраняются транзакционно.

```sh
adb devices -l

adb shell am force-stop com.aistudio.wordsgame.kymxpv
adb shell monkey -p com.aistudio.wordsgame.kymxpv 1
```

## 10. Риски и ограничения

1. **Нет устройства/эмулятора.** Все строки §7 — `NOT RUN`; P0 не
   сертифицирован на устройстве. Это главное ограничение отчёта.
2. **TalkBack и IME** проверены только по семантике и тестам; фактическое
   озвучивание, фокус, автокоррекция и клавиатура требуют ручного прогона.
3. **320/360 dp и 200%** проверены layout-тестами, которые не запускались на
   устройстве; возможны различия шрифтов производителя.
4. **Устаревшие connected-тесты исправлены, но не запущены.** При первом
   прогоне на устройстве возможны другие stale-ожидания; это не повод
   ослаблять проверки.
5. **Черновик после Back** не сохраняется (P2-1); это не потеря прогресса, но
   требует продуктового решения.
6. **Публикация** остаётся заблокированной ручным аудитом прав определений
   (`audit.passed=false`, `rights_review.passed=false`); UXF-02 не меняет
   этот статус.
