# Лестница подсказок на экране уровня

LCH-03: игровой UI получает смысловые тексты только из минимального набора
`docs/owned_hints.json` (LCH-02). В установленной SQLite-БД 39 собственных
описаний, 0 толкований Викисловаря. Словарь и short15 (15/49, R/M, цели)
не изменены. Статус текстов и лицензии — pending-owner-approval; лицензия
не назначена. Документы LCH-02 остаются историческим снимком до установки.

T4: все 11 обязательных целей имеют пригодные собственные загадки.
T3 принимает **любой** составимый словарный ответ нужной длины; hintTarget
используется только для назначения подсказки. T6 засчитывает любые четыре
слова из **всех 20** утверждённых профессий; число текстов не ограничивает пул.
T1/T2/T5/T7 используют прежние правила. Показ ответа сам его не засчитывает.

Экран показывает все открытые шаги текущей цели, номер ступени, цену следующего
шага и остаток. Лестница: тема (если достоверна и не раскрывает ответ), описание
(только при наличии пригодного собственного текста), длина, первая буква,
неполный шаблон, ответ. Отсутствующие тема/описание не создают ступени,
не расходуют бюджет и не увеличивают счётчик показов. Нет поиска запасного
толкования в старой БД. Для произвольного слова вне набора SQL возвращает
пустой список текстов; категория читается независимо от описаний.

Бюджеты, единица за четыре найденных слова, бесплатные тема/описание/длина
для T4 сохранены. Цель живёт до её угадывания, включая завершение задания
другим ответом; затем выбирается новая. Random и доступность описания
не ограничивают допустимые игровые ответы. UI показывает только открытые
ступени; неполный шаблон не заменяется полным ответом.

`GameViewModel` читает локальные метаданные составимых ненайденных ответов
на IO, готовит текст на Default. Во всех игровых ветках дополнительно
отбрасывает записи, у которых origin не own или source не пуст.
`DefinitionHint` сохраняет защиту от ответа, форм и родства. `GameScreen`
показывает подготовленное состояние; старые тексты/источники в него не попадают.
Отсутствующая/повреждённая БД безопасно включает буквенный резервный режим,
включая T4. Это аварийный режим: сборка без пригодных обязательных T4 запрещена.

## Данные и воспроизводимость

```sh
python3 tools/build_owned_hints.py          # пересобрать только БД и manifest
python3 tools/build_owned_hints.py --check  # пересборка во временный файл и SHA
python3 -m tools.owned_hints                # проверить текущий набор LCH-02
```

Генератор не сочиняет тексты, не меняет слова/кампанию и не читает старые
толкования при обычной сборке. Входы — авторский JSON и фиксированный
`tools/owned_hint_index.json`. Схема DefinitionsRepository сохранена для
совместимости инструментов с отсутствующими/частичными описаниями.
Остальные слова получают пустые списки форм/родства и, если рубрика неизвестна,
`other`; их словарное принятие не зависит от БД.

Индекс — 2562 записи с ключом/происхождением категории; формы/родство сохранены
только для 39 целей, без предложений, примеров, глосс или скрытых определений.
Это тексто-свободный снимок прежней word_metadata, привязанный к принятому
CUR-03 пакету и дампу SHA-256
`98bebfb8013064d23bc6f0981b64cd097f64e098c9e434ebb97684c9606cc2da`.
Перед однократным извлечением проверены локальный дамп и весь набор LCH-02
против всех 31 369 прежних толкований; совпадений по критерию LCH-02 нет.
`--extract-index --dump <файл>` предназначен только для такого исходного
перехода, а не для повторного извлечения из уже минимальной БД.

Источники рубрик сохранены по словам: структурированные поля/правила
(`sense.*`, `leading_label`, `gloss_head`), прежняя независимая классификация
(`ai:...`) и решения владельца (`owner:...`). Все 20 T6 имеют
`owner:SHORT15-05:2026-11-16`; независимый пересчёт полного множества обязателен.
Новые провайдеры, ключи и сеть не использовались. Для производного словарного
индекса сохранены атрибуция участников Викисловаря, адреса статей в
word_sources.jsonl.gz и CC BY-SA 4.0; эти данные не объявлены собственными
описаниями. Уведомления: legal/THIRD_PARTY_NOTICES.txt.

`verifyOwnedHints` обязателен перед `verifyDictionaryLicenses`/sync/build:
проверяет входные SHA, роли, пригодность **всех** T4, полный T6 и побайтовое
равенство SQLite свежей сборке. Проверяются также пустые вспомогательные поля,
схема, word_metadata и отсутствие старых свободных страниц через равенство
с заново созданной БД. Старый пакет нельзя установить поверх минимального:
защита действует до резервного копирования в short15-install и в общем publish.
Для изменения кампании/словаря нужен новый согласованный исходник, а не
возврат старых толкований. Неполные описания читаются редакторскими инструментами
с прежним API; исторические инструменты могут готовить кандидаты отдельно.

В строгом release обязательны те же проверки независимо от waiver, плюс
ручной аудит **всех 39** записей (0 плохих, SHA текущей БД), подтверждение прав
и лицензия владельца. Старое правило выборки ≥300 сохраняется для прежних
больших баз. Сейчас audit.passed/rights_review.passed=false. Уже существующий
waiver допускает лишь технический APK, publishable=false; публикация запрещена.

## Обновление и сохранения

`SqliteDefinitionsRepository` на первом чтении сверяет asset с BuildConfig SHA,
сравнивает распакованную БД по содержимому и атомарно заменяет любое отличие,
даже при равной или большей старой user_version. При отсутствующем/непригодном
asset старая БД удаляется и не открывается. SQL/копирование/хэширование — на IO.
Прогресс хранится в другом файле и не удаляется.

Старый DataStore может содержать уже подготовленное чужое определение.
Поле HintStateDto.ownedContentVersion по умолчанию 0: при чтении таких снимков
core удаляет **все** DEFINITION-ступени (включая прежние без wiktionary-флага),
пересчитывает индекс открытого префикса и сохраняет цель, позиции, shownSteps
и paidUnits. Исторический расход не возвращается и не списывается повторно.
Найденные слова, звёзды, навигация, остальные ключи DataStore не меняются.
Следующая запись кампании сохраняет очищенный снимок с версией 1; новые
собственные ступени переживают перезапуск даже без БД.

Проверки: OwnedHintsTest/HintRulesTest (JVM), test_owned_hints_install
(Python), SqliteDefinitionsRepositoryTest, CampaignProgressRepositoryTest,
GameViewModelTest (Android). Выполнение Android instrumentation на устройстве
обязательно отмечается отдельно: компиляция не заменяет прогон.
