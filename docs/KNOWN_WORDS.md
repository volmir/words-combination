# Общий фильтр известных слов — BLOOM-01

`KnownWords` — вероятностный справочник полного входа `clean_dictionary`,
не список ответов и не основание для зачёта. `mightContain(raw)` возвращает
`false` для пустого нормализованного ввода; положительный результат может быть
ложным. Точный игровой словарь и правила букв продолжают определять зачёт.
`KnownWords.read(bytes)` возвращает `null` при отсутствии или повреждении файла.
Отсутствие фильтра не ограничивает работу точного словаря. Подключение assets,
Gradle и UI отложено до переключения данных; текущая игра не менялась.

## Бинарный формат v1

Все целые беззнаковые 32-битные, little-endian. Заголовок 28 байт:

| Смещение | Поле |
|---|---|
| 0 | 8 байт magic: ASCII `RUKNOWN` и нулевой байт |
| 8 | Версия: 1 |
| 12 | Число бит m, кратное 8, от 8 до 134217728 |
| 16 | Число хэшей k: 1..8 |
| 20 | Число различных непустых нормализованных слов: 1..2147483647 |
| 24 | Идентификатор алгоритма хэширования: 1 |
| 28 | m/8 байт битового массива |
| 28+m/8 | SHA-256 всех предшествующих байтов (32 сырых байта) |

Файл должен иметь ровно 28+m/8+32 байта. Неизвестные версии и алгоритмы,
недопустимые параметры, обрезанные файлы, хвостовые байты и несовпадение
контрольной суммы отклоняются. JVM-читалка копирует вход, проверяет размер до
копирования и не сохраняет изменяемые внешние массивы. Контрольная сумма
защищает от случайного повреждения, но не подтверждает подлинность.

Нормализация совпадает с `Alphabet.normalize`: нижний регистр, ё→е,
удаление всех символов вне `Alphabet.LETTERS`. NFC и дополнительные ограничения
длины не применяются. Тестовые векторы включают пунктуацию и разложенные ё/й.

Алгоритм 1: SHA-256 UTF-8 нормализованного слова разбивается на восемь
беззнаковых u32 little-endian. Первые k значений дают позиции `u32 % m`.
Бит i хранится в байте i/8, маска `1 << (i % 8)` (младший бит первым).
Процессный `hash()` и случайные соли не используются.

Размер: `m = ceil((-n*ln(p)/ln(2)^2)/8)*8`, p=0.01;
`k = clamp(round(m/n*ln(2)), 1, 8)` (Python round, половина к чётному).
Порядок входных слов не влияет на результат.

## Воспроизведение и проверка

Из корня репозитория, без сети и регенерации игрового набора:

```sh
python3 tools/build_known_words.py \
  --source-words tools/cache/cleanup/source-vocabulary-98bebfb8013064d23bc6f0981b64cd097f64e098c9e434ebb97684c9606cc2da.json \
  --candidate .local/known_words/candidate
python3 -m unittest tools.tests.test_known_words
bash ./gradlew :core:test --tests 'com.example.sostavslova.core.KnownWordsTest' --console=plain
```

`--source-words` принимает кэш JSON с `words` либо полный построчный список.
До нормализации проверяются количество и SHA-256 канонического источника:
отсортированное множество строк, UTF-8, LF после каждой строки, как в
`clean_dictionary`. Ожидания берутся из `selection.input_words_sha256` и
`selection.input_words` манифеста (`--manifest`). Это не частотный список и
не очищенный игровой словарь. Несовпадение прекращает генерацию.
Вход уже извлечён из закреплённого дампа; повторное чтение статей не нужно.
`--game-words` задаёт точный игровой словарь для проверки (по умолчанию data/words.txt).

В каталоге кандидата создаются `known_words.bloom` и `known_words_report.json`.
Отчёт содержит хэши источника, игрового словаря и бинарного файла, параметры,
ожидаемый и измеренный FPR. Проверяются все слова полного источника и игрового
словаря; игровые слова вне полного источника вызывают ошибку. Отрицательная
выборка: 100000 различных случайных строк алфавита длины 3..16,
`random.Random(20261111)`, без слов полного источника. Её порядок и SHA-256
зафиксированы отчётом. FPR оценивается на синтетических отрицательных, а не
на произвольном распределении реального пользовательского ввода.

Полученный снимок (113413 исходных, 23393 игровых слова):

- input SHA-256: `c419c65f916799955584130390527b60642ec6f26c6228bdd7058a95986d6415`;
- m=1087072, k=7, размер 135944 байта (132.76 КиБ);
- ложноотрицательных 0; ложноположительных 935/100000, FPR 0.935%;
- бинарный SHA-256: `356d308abddcc3cdc42b90e319327f6c12ebf60b7d7ec62dce1ccbf2bf5166a6`;
- SHA-256 отрицательных: `97cd0a5b3d5a48a8b81de82a68e0b5a72e2853e34d3125872a2d0826993c068d`.

Общие синтетические Python/JVM-векторы: `tools/known_words_vectors.json`;
содержат исходные слова, точные бинарные байты и ожидаемые ответы.
Тесты проверяют воспроизводимость, нормализацию, порчу каждого байта,
обрезание на каждой позиции, неверные заголовки с корректной контрольной
суммой и независимость зачёта от фильтра. Реальные файлы остаются в локальном
кандидате, без добавления в data/assets и без изменения Gradle.
