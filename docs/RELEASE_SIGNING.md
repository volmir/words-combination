# Локальная подпись Android

Debug использует штатную конфигурацию AGP `debug` и её локальное хранилище
(`~/.android/debug.keystore` в обычном окружении). Корневой `debug.keystore`
не нужен. Эта подпись предназначена только для разработки.

Release использует только отдельную конфигурацию `release`. Без настроенного
ключа `signingConfig = null`: при отдельно разрешённой сборке AGP создаст
`app/build/outputs/apk/release/app-release-unsigned.apk`. Это **неподписанный
артефакт, НЕ предназначенный для публикации или установки**.

## Настройка владельцем

Используйте уже существующий отдельный ключ владельца. Эта инструкция
не создаёт ключ и не разрешает сборку или публикацию release.

В корне проекта создайте локальный `keystore.properties` с четырьмя полями
(значения ниже — плейсхолдеры):

```properties
storeFile=/absolute/path/to/owner-release.jks
storePassword=<STORE_PASSWORD>
keyAlias=<RELEASE_ALIAS>
keyPassword=<KEY_PASSWORD>
```

Относительный `storeFile` разрешается от корня репозитория, `~` не раскрывается.
Файл читается как Java Properties: экранируйте обратные слеши и специальные
символы по этому формату. Ограничьте доступ к файлу: `chmod 600 keystore.properties`.
Предпочтительно хранить сам ключ за пределами репозитория.

Вместо файла можно передать через защищённое окружение четыре переменные:

| Поле файла | Переменная окружения |
| --- | --- |
| `storeFile` | `SOSTAVSLOVA_RELEASE_STORE_FILE` |
| `storePassword` | `SOSTAVSLOVA_RELEASE_STORE_PASSWORD` |
| `keyAlias` | `SOSTAVSLOVA_RELEASE_KEY_ALIAS` |
| `keyPassword` | `SOSTAVSLOVA_RELEASE_KEY_PASSWORD` |

Переменные имеют приоритет для каждого поля; даже пустая переменная заменяет
значение из файла. Все четыре поля должны быть непустыми. Частичная настройка
блокирует release; автоматического перехода к debug-подписи нет.
Не передавайте пароли аргументами команд, не выводите окружение и не включайте
shell tracing (`set -x`) или диагностический Gradle `--debug` при работе с секретами.
`keystore.properties`, `*.keystore`, `*.jks`, `*.p12`, `*.pfx` исключены из Git.

Без сборки APK проверьте настройку:

```bash
bash ./gradlew :app:verifyReleaseSigning --console=plain
```

Без настройки задача явно предупреждает о неподписанном артефакте. При полной
настройке она проверяет доступность хранилища, пароль хранилища, наличие ключа
и сертификата. `debug.keystore`, alias `androiddebugkey` и сертификат с
`CN=Android Debug` запрещены, включая переименованные хранилище и alias.
Пароль самого ключа дополнительно проверяется AGP при подписании; успешная
предварительная проверка не доказывает наличие подписанного APK.
Проверка автоматически включена в release-задачи; действующие лицензионные
проверки и утверждённые SHA-256 продолжают действовать независимо от подписи.

## Проверка APK после отдельно разрешённой сборки

Используйте `apksigner` из установленных Android SDK Build Tools:

```bash
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --verbose --print-certs \
  app/build/outputs/apk/release/app-release.apk
```

Требуются код возврата 0 и SHA-256 сертификата, совпадающий с сертификатом
ключа владельца. Его можно посмотреть командой ниже: пароль вводится в
интерактивном запросе, не в аргументах и не в журнале.

```bash
keytool -list -v -keystore /absolute/path/to/owner-release.jks -alias RELEASE_ALIAS
```

Подпись debug-сертификатом может успешно пройти `apksigner verify`, поэтому
обязательно сверяйте сертификат и отпечаток. Для неподписанного APK проверка
`apksigner verify` должна завершиться ошибкой; такой файл не готов к установке
или публикации. Не используйте старый APK из `build/` как свидетельство новой
проверки. Даже действительная release-подпись не означает разрешение публикации.

Справка: [подпись приложения](https://developer.android.com/studio/publish/app-signing),
[apksigner](https://developer.android.com/tools/apksigner).
