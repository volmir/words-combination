# Работа с Codex (и Claude) над проектом

Инструкция для разработки приложения сразу двумя агентами. Команды и ключи конфигурации Codex меняются быстро — перед первым запуском сверьтесь с официальной документацией (developers.openai.com/codex: *Config basics*, *Config reference*, *Sandbox and approvals*, *AGENTS.md*). Ниже — то, что подтверждается текущими справочниками, и отдельно отмечено то, что нужно проверить.

## 1. Что у вас уже есть

* **`AGENTS.md` в корне** — Codex подхватывает его автоматически (это его «память проекта»). Файлы из каталогов вложенных папок добавляются сверху вниз, поэтому при необходимости можно положить дополнительный `AGENTS.md` в `app/` или `core/`.
* **`CLAUDE.md`** — для Claude Code. Чтобы правила не расходились, в нём лишь импорт `@AGENTS.md` плюс заметки для Claude. **Единственный источник правил — `AGENTS.md`**: правьте только его.
* Лимит на размер подгружаемых инструкций у Codex по умолчанию около 32 КБ (`project_doc_max_bytes`) — текущий `AGENTS.md` занимает ~4 КБ, не раздувайте его: подробности держите в `docs/`.
* **Не запускайте `/init`** в Codex: команда создаёт новый шаблон `AGENTS.md` и может затереть ваш.

## 2. Установка и первый запуск

```bash
# один из вариантов установки (проверьте актуальный в документации)
npm install -g @openai/codex        # или: brew install codex
cd words-offline
git init && git add -A && git commit -m "Initial import"
codex                                # интерактивный режим в корне репозитория
```

Авторизация — через аккаунт ChatGPT или API-ключ (выберите при первом запуске).

Первая проверка, что Codex видит правила: спросите «Какие у тебя инструкции для этого проекта? Перечисли ключевые правила». Он должен назвать правила из `AGENTS.md` (офлайн, `:core` — источник логики, нет HTML и т.д.).

## 3. Песочница, подтверждения и Android/Gradle

Codex запускает команды в песочнице. Основные режимы (флаги `-s/--sandbox` и `-a/--ask-for-approval`, либо `/permissions` в сессии): `read-only`, `workspace-write`, `danger-full-access`; подтверждения: от «спрашивать про всё» до «по запросу». Для этого проекта разумно:

* **`workspace-write` + подтверждения по запросу** (`--full-auto` — сокращение именно для этого сочетания).
* `danger-full-access` / `--yolo` — **не использовать** на машине с рабочими ключами и личными файлами.

Особенности именно Android/Gradle:

| Проблема | Решение |
|---|---|
| Gradle должен писать в `~/.gradle` (кэш) и `~/.android` — это вне рабочей папки | Запускать с дополнительными каталогами для записи: `codex --add-dir ~/.gradle --add-dir ~/.android` |
| В песочнице по умолчанию нет сети → Gradle не скачает зависимости | **Один раз** откройте проект в Android Studio и выполните Gradle Sync (или `./gradlew :core:test :app:assembleDebug` в обычном терминале), чтобы заполнить кэш. Дальше сборка пойдёт офлайн (`./gradlew --offline ...`). Если нужна сеть в песочнице, включите её в `.codex/config.toml` (ключ см. ниже — **проверьте имя в Config reference**) |
| `SDK location not found` | Создайте `local.properties` с `sdk.dir=/путь/к/Android/Sdk` (файл в `.gitignore`) или задайте `ANDROID_HOME` |
| Нужна JDK 17 | `java -version` должен показывать 17; задайте `JAVA_HOME` |
| Эмулятор/`adb` и UI-тесты | Агенту их запускать неудобно. Запускайте `connectedDebugAndroidTest` сами и вставьте результат в сессию |

Проектный конфиг лежит в `.codex/config.toml` (применяется для доверенных проектов — Codex спросит доверие при первом запуске):

```toml
approval_policy = "on-request"
sandbox_mode = "workspace-write"
# Сеть для песочницы workspace-write (НЕ включено по умолчанию; проверьте точное имя
# таблицы/ключа в Config reference вашей версии Codex, прежде чем раскомментировать):
# [sandbox_workspace_write]
# network_access = true
```

Файл уже добавлен в пакет. Личные настройки (модель, уровень «размышлений») держите в `~/.codex/config.toml`, а не в репозитории.

## 4. Как запускать этапы из `PROMPTS.md`

Шаблон запуска одного этапа (подставьте номер):

```text
Прочитай AGENTS.md. Выполни ТОЛЬКО «Этап N» из docs/PROMPTS.md — текст этапа и критерии приёмки возьми из файла.
Работай в ветке stage-N. Не переходи к следующему этапу.
В конце дай отчёт в формате из AGENTS.md (раздел «Отчёт по этапу»).
```

В интерфейсе Codex удобно добавить файл в контекст через `@docs/PROMPTS.md`. Правила запуска:

1. Один этап — одна сессия и одна git-ветка (`stage-1`, `stage-2` …); после приёмки — merge в `main`.
2. Этап 0 (проверка `:core`) можно запустить без диалога: `codex exec "Выполни Этап 0 из docs/PROMPTS.md"`. Для остальных лучше интерактивный режим — вы подтверждаете правки.
3. Если агент «забывает» правила, напомните: «Сверься с AGENTS.md пункты 1–5». Повторяющуюся ошибку добавьте в `AGENTS.md` одной строкой (так Codex учится на проекте).
4. Не вставляйте промпты целиком каждый раз — ссылка на файл экономит контекст.

## 5. Два агента: как не мешать друг другу

Рекомендуемая схема — **один исполнитель на этап, второй — независимый ревьюер**:

| Шаг | Кто | Что делает |
|---|---|---|
| 1 | Codex (или Claude) | Выполняет этап N в ветке `stage-N`, коммитит |
| 2 | Другой агент | Ревью диффа по промпту ниже, **без правок** кода |
| 3 | Вы | Решаете, какие замечания принять; исполнитель их исправляет |
| 4 | Вы | Запускаете приложение/тесты вручную, merge |

Почему так: вторая модель замечает другие ошибки, а ревью без права правки не создаёт конфликтов. **Не запускайте двух агентов одновременно в одной ветке/папке.** Если нужен параллелизм — `git worktree add ../words-codex stage-N` для каждого.

Распределение этапов (предложение, меняйте по вкусу): этапы 1–2, 9–11 (Gradle, данные, надёжность, релиз) — Codex; этапы 3–8 (экраны и компоненты по DESIGN.md) — Claude; ревью каждого этапа — «противоположный» агент.

### Промпт ревьюера (одинаков для Codex и Claude)

```text
Ты ревьюер, не исполнитель: код НЕ меняй, файлы не правь.
Прочитай AGENTS.md, docs/SPEC.md, docs/DESIGN.md, docs/BUGFIXES.md и «Этап N» из docs/PROMPTS.md.
Просмотри git diff main...stage-N и проверь:
1. Выполнены ли все пункты этапа и критерии приёмки (по каждому: выполнено / нет / не проверено).
2. Нарушены ли правила AGENTS.md (логика дублируется вместо :core, сеть, HTML, !!, строки не в strings.xml).
3. Повторены ли ошибки оригинала из docs/BUGFIXES.md.
4. Соответствуют ли тексты и цвета DESIGN.md дословно.
5. Что может сломаться: поворот экрана, убийство процесса, большой шрифт, пустые состояния.
Выведи список замечаний по убыванию серьёзности: файл:строка — проблема — как исправить. Не пиши «всё хорошо», если не проверил: отмечай, что проверено, а что нет.
```

## 6. Полезные команды Codex (проверено по справочникам, названия могут меняться)

| Команда | Зачем |
|---|---|
| `/permissions` | сменить режим подтверждений в сессии |
| `/model` | сменить модель / уровень рассуждений |
| `/review` | встроенное ревью (если есть в вашей версии) — как дополнение к промпту выше |
| `/diff` | показать текущие изменения |
| `@путь` | добавить файл в контекст |
| `!команда` | выполнить shell-команду напрямую |
| `codex exec "..."` | неинтерактивный запуск (для этапа 0, CI) |

## 7. Облачный Codex (Codex Web) — если решите использовать

Облачному агенту нужно собрать окружение: JDK 17, Android SDK (command-line tools, platform и build-tools нужной версии, принятые лицензии), зависимости Gradle. Обычно сеть доступна на шаге подготовки (setup script) и ограничена во время работы агента — поэтому всё, что требует скачивания, нужно сделать в setup script (например, `./gradlew :core:test :app:assembleDebug --no-daemon`, чтобы прогреть кэш). Подробности и актуальные ограничения — в документации «Codex cloud / environments». Для первых этапов (0–2) облако не обязательно; интерактивный CLI на вашей машине проще отладить.

## 8. Частые проблемы

* **Агент «успешно завершил» этап, но ничего не запускал.** Требуйте в отчёте вывод команд (`./gradlew :core:test`, `:app:assembleDebug`) и список непроверенного — это закреплено в `AGENTS.md`.
* **Агент переписывает `:core`.** Напомните правило №1; в крайнем случае запретите правки каталога: «`core/` — только чтение, меняй через предложение в отчёте».
* **Правки `words.txt` руками.** Правило №3: только через `tools/build_dictionary.py`.
* **Разошлись `AGENTS.md` и `CLAUDE.md`.** Правьте только `AGENTS.md`; `CLAUDE.md` содержит импорт. Если ваша версия Claude Code не поддерживает `@`-импорт — скопируйте содержимое вручную.
