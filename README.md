# Составь слова — автономное Android-приложение

Автономная интеллектуальная игра-головоломка на **Kotlin + Jetpack Compose** с модульной архитектурой (`:core` + `:app`).  
Цель игры: составить как можно больше слов из букв длинного исходного слова.  
Приложение работает **100% офлайн, без интернета, без рекламы, аналитики и системных разрешений**.

## 1. Архитектура проекта

Проект разделён на два модуля:

```
├── core/                       # Чистая Kotlin-библиотека (JVM) — единый источник игровой логики
│   └── src/
│       ├── main/kotlin/        # WordIndex, GameState, LevelRules, DefinitionHint, RussianPlural, Alphabet
│       └── test/kotlin/        # 42 JVM-теста и инструмент аудита всех подсказок
├── app/                        # Модуль Android-приложения (Jetpack Compose, Material 3)
│   └── src/
│       ├── main/kotlin/        # UI (экраны, компоненты, тема), Data (репозитории), DI, Навигация
│       ├── androidTest/        # Compose UI instrumented-тесты для ключевых сценариев
│       └── main/assets/        # Сгенерированные копии словаря, уровней, БД и уведомлений
├── data/                       # Словарь, 30 уровней, definitions.db, манифест и происхождение
├── legal/                      # Лицензионные тексты сторонних библиотек и словаря
└── tools/                      # Утилиты генерации и проверки словаря (Python 3)
```

### Принцип разделения ответственности:
- **`:core` — источник истины для логики:** правила игры, поиск комбинаций через мультимножества букв (`WordIndex`), состояние раунда (`GameState`), задания уровней (`LevelRules`), нормализация (`ё`→`е`) и склонение числительных (`RussianPlural`). Не зависит от Android SDK.
- **`:app` — презентация и хранение:** UI на Jetpack Compose (M3), `ViewModel` + `StateFlow`, навигация (Navigation Compose), локальное сохранение прогресса в Jetpack DataStore Preferences (`ProgressRepository`).

## 2. Игровые экраны и функциональность

1. **Главный экран (`HomeScreen`)**
   - Ввод любого слова игроком (длина 3–30 букв, автоматическая нормализация).
   - Быстрый старт раунда со случайным длинным словом (кнопки обновляются).
   - Карточка «Продолжить игру» с отображением текущего прогресса.
   - Описание игры и правил.

2. **Экран игры (`GameScreen`)**
   - Плитки букв исходного слова и строка счёта: «всего найдено N слов, вы отгадали M».
   - Поле проверки ответа с валидацией (баннеры «Правильно!», «Уже разгадано», «Не найдено»).
   - Список разгаданных слов (WordLinks).
   - Подсказки через значение с маскированием ответа и родственных слов; первая буква и длина при отсутствии пригодного текста.
   - Полные толкования и источник для уже найденных слов.
   - Диалог подробной статистики по длине найденных слов (`StatsTable`).
   - Диалог заданий и звёзд для уровней кампании (`LevelRules`).
   - Кнопка «Завершить игру» с подтверждением.
   - Автоматическое сохранение состояния раунда в DataStore.

3. **Прохождение кампании (`LevelsScreen`)**
   - 30 уровней возрастающей сложности.
   - Сетка уровней с отображением заработанных звёзд (★ 0..3) и блокировкой закрытых уровней.
   - Уровень открывается при успешном прохождении предыдущего (★1).

4. **Поиск слов (`WordSearchScreen`)**
   - Встроенный инструмент анализа: находит все допустимые слова из введённой комбинации букв.
   - Вывод общего количества и группировка слов по длине в алфавитном порядке.

5. **Статические экраны**
   - **Правила (`RulesScreen`):** подробные правила игры.
   - **Об игре (`AboutScreen`):** версия сборки, динамический подсчёт слов в базе, лицензии и источники.

## 3. Словарь и лицензии данных

Происхождение игровых данных:
- **`words.txt`:** игровая база русских нарицательных существительных после очистки исходных 113 413 слов из дампа Kaikki.org / Wiktextract. Данные Викисловаря — **CC BY-SA 4.0**; актуальное число слов и хэши записаны в `data/manifest.json`.
- **`word_sources.jsonl.gz`:** сохраняет URL исходных статей; история авторства доступна по этим адресам.
- **`levels.json`:** 30 уровней на базе проекта `volmir/words-api` под лицензией **MIT**.
- **Определения:** по явной задаче владельца включены локальные толкования и подсказки через значение (`BuildConfig.HAS_DEFINITIONS = true`). При отсутствии пригодного значения работает подсказка с длиной и первой буквой. Полный текст с источником доступен после отгадывания; в подсказке ответ, формы и распознанные однокоренные слова заменяются на `***`. Для release непроверенная база не допускается. [Сборка и обработка подсказок](docs/LOCAL_DEFINITIONS.md).
- **Текущая игровая база:** отбор по пометам значений и частотам словоформ, без ИИ. Прежние включения, исключения, лимит кандидатов и наличие определения на результат не влияют. Историческое решение v1 сохраняло слова уровней с четырьмя заменами и прежними порогами. [История решения](docs/decisions/2026-11-06-clean-game-vocabulary.md). Для всего перехода v2 действует [контракт кампании](docs/CAMPAIGN.md), разрешающий замену старых слов и порогов, алгоритмы и ИИ при подготовке категорий и спорного отбора.
- **Подготовка игрового набора:** по умолчанию `tools/build_game_data.py` запускает `--definitions-source clean`, реализованный в `tools/clean_dictionary.py`. Параметры — блок `cleanup` в `tools/selection_config.json`, процедура — [docs/DICTIONARY_CLEANUP.md](docs/DICTIONARY_CLEANUP.md). Каждое решение и исключения для уровней сохраняются в отчёте. Это автоматический первый проход; ручной аудит выборки ещё требуется.
- **Прежние определения:** эксперимент для 60 000 кандидатов сохранён в кэше и доступен явно через `--definitions-source dump`; собственная генерация — через `own`. Он не определяет состав игровой базы. [Политика определений](docs/DEFINITIONS_POLICY.md).

Толкования для текущего очищенного словаря собираются отдельно, без изменения слов и уровней:

```bash
python3 tools/build_local_definitions.py --dump .local/dictionary/raw-wiktextract-data-2026-11-01.jsonl.gz
```

Это временные определения из локального дампа, без ИИ и сети; ручной аудит и индивидуальная проверка прав не пройдены. Источник каждого текста сохраняется. Генератор также экспортирует все случаи для проверки маскирования кодом `:core`.

Локальный дамп от 2026-11-01 хранится в `.local/dictionary/raw-wiktextract-data-2026-11-01.jsonl.gz`, контрольный снимок до удаления фильтра — в `.local/dictionary/baseline/`. Каталог `.local/` исключён из Git и не появляется при клонировании. Перед пересборкой SHA-256 дампа должен совпадать с `source.sha256_input` в `data/manifest.json`; диагностический скрипт проверяет это автоматически. Скрипты ничего не скачивают.

```bash
python3 tools/diagnose_missing_words.py --wiktionary-jsonl .local/dictionary/raw-wiktextract-data-2026-11-01.jsonl.gz
python3 tools/build_game_data.py --dump .local/dictionary/raw-wiktextract-data-2026-11-01.jsonl.gz --frequency-list .local/frequency/frequencywords-2018-ru/ru_full.txt --prepare-only
```

Когда `definitions.db` уже подключена, очистка напрямую не заменяет рабочие данные. Сначала подготовьте словарь командой выше, затем передайте путь `candidate` из её вывода сборщику определений:

```bash
python3 tools/build_local_definitions.py --dump .local/dictionary/raw-wiktextract-data-2026-11-01.jsonl.gz --manifest /путь/из/candidate/manifest.json --out data
```

Формат UTF-8: `словоформа число_употреблений`, по одной записи на строку. Частоты уникальных форм каждого слова суммируются; регистр, ударения и ё нормализуются. Для очистки нужен `--frequency-list`; в прежних режимах `dump` и `own` вместо него можно передать `--corpus`, а без обоих частотность пропускается. Тип источника и SHA-256 учитываются в кэше и записываются в `manifest.selection` и отчёт. Список обрабатывается локально и не служит источником новых игровых слов. Нулевая частота не получает ранга и сама по себе не доказывает редкость слова: такие слова откладываются на проверку, без включения в первый игровой набор. Локальный FrequencyWords содержит данные OpenSubtitles 2018; README закреплённой версии указывает CC BY-SA 3.0.

Отчёты игрового конвейера находятся в `build/reports/`. Отчёты прежней полной пересборки — в `build/reports/dictionary/`, включая подкаталог `before-source-filter-removal/`. Каталог `build/` исключён из Git и может удаляться при очистке сборки. Дамп и контрольный снимок сохраняются отдельно от него. JDK устанавливается вне проекта.

## 4. Сборка и запуск

### Требования к окружению:
- **JDK:** OpenJDK 21 (Temurin или совместимый).
- **Android SDK:** `compileSdk 36`, `targetSdk 36`, `minSdk 24` (Android 7.0+).
- **Gradle:** 9.3.1 через Gradle Wrapper; AGP 9.1.1, Kotlin 2.2.10.

Для сборки приложения задайте существующий Android SDK в `local.properties` (`sdk.dir=...`) или `ANDROID_HOME`. На текущей машине SDK установлен: `sdk.dir` указывает на `~/.local/share/words-combination/android-sdk` (platform android-36, build-tools 36.0.0), также заданы `ANDROID_HOME` и `ANDROID_SDK_ROOT`; однако компиляция Android, lint, APK и инструментальные тесты пока не подтверждены успешным прогоном. `:core` работает с JDK 21 без Android SDK. Wrapper в текущем репозитории запускается через `bash`.

### Основные команды:

```bash
# 1. Запуск unit-тестов игровой логики (:core)
python3 -m unittest discover tools/tests
bash orchestrator/run.sh --check orchestrator
bash ./gradlew :core:test

# 2. Сборка отладочного APK
bash ./gradlew :app:assembleDebug
# Выходной файл: app/build/outputs/apk/debug/app-debug.apk

# 3. Сборка релизного APK с R8 minification и сжатием ресурсов
bash ./gradlew :app:assembleRelease
# После успешной сборки: app/build/outputs/apk/release/app-release.apk

# 4. Сборка релизного Android App Bundle для публикации
bash ./gradlew :app:bundleRelease
# После успешной сборки: app/build/outputs/bundle/release/app-release.aab

# 5. Запуск UI-тестов на подключённом эмуляторе/устройстве
bash ./gradlew :app:connectedDebugAndroidTest
```

Release-команды сейчас должны завершаться отказом проверки `verifyDefinitionsAudit`: определения имеют временную политику `wiktionary-provisional-v1`, `audit.passed=false`. Даже установка SDK не снимает этот блок. Для проверки данных без сборки APK доступны `bash ./gradlew :app:verifyDictionaryLicenses :app:syncDictionaryAssets`.

### Оркестратор задач разработки

В `orchestrator/` подключён последовательный запуск задач через CLI-агента
(Codex CLI или OpenCode):
задача → проверки проекта → запись результата → локальный Git-коммит.
Нужны Bash, Python 3.10+, Git и один авторизованный CLI-агент (`codex` или
`opencode`); для сборок — JDK 21 и Android SDK из требований выше.
Зависимости Android-приложения не меняются.

```bash
bash orchestrator/run.sh --dry-run                      # план без запуска моделей и изменений
bash orchestrator/run.sh --check full                   # Python-тесты, :core:test, :app:assembleDebug
bash orchestrator/run.sh                                # выполнение сохранённой в Git очереди
bash orchestrator/run.sh --backend opencode --models paid  # платный набор моделей OpenCode
```

Рабочая очередь [orchestrator/TASKS.md](orchestrator/TASKS.md) изначально пуста.
Добавьте согласованные задачи и сохраните изменения коммитом перед запуском.
По умолчанию используется ветка `auto/tasks`, push включён (`--no-push` отключает
его на один запуск). Бэкенд (`codex`/`opencode`), модели (бесплатный набор по
умолчанию и платный `--models paid`) и таймауты — в [config.json](orchestrator/config.json),
формат задач, дополнительные проверки и продолжение после ошибки — в
[инструкции оркестратора](orchestrator/README.md).
Некорректно настроенный SDK останавливает полный гейт; в текущем окружении SDK
установлен (platform android-36, build-tools 36.0.0). Проверка release по-прежнему
требует ручного аудита определений.

## 5. Правила разработки

1. **Источник инструкций:** `AGENTS.md` в корне репозитория.
2. **Генерация:** файлы `data/` меняются только через `tools/`; дампы, частотный список, кэш и локальные отчёты в Git не входят. При клонировании готовые игровые данные доступны, но для их регенерации нужны локальные входы с согласованными SHA-256.
3. **Безопасность репозитория:**
   - Коммит в репозиторий **не запускает** релизную публикацию и не публикует версию 1.0.0. Публикация в Google Play требует ручного создания ключа подписи и загрузки бандла через Google Play Console.
   - `keystore.properties`, локальные ключи и `local.properties` включены в `.gitignore`.

## 6. Приватность и безопасность (Google Play Data Safety)

- **Разрешения:** Манифест `AndroidManifest.xml` не содержит ни одного разрешения (`<uses-permission>`), включая сетевое разрешение `INTERNET`.
- **Сбор данных:** Приложение **не собирает**, не хранит на серверах и не передаёт никакие персональные или технические данные пользователей.
- **Реклама и аналитика:** Полностью отсутствуют SDK рекламы (AdMob и др.) и телеметрии/аналитики.
- **Хранение данных:** Все пользовательские данные (прогресс уровней, сохранённая игра) хранятся исключительно на устройстве пользователя в закрытой директории приложения и удаляются при деинсталляции.
